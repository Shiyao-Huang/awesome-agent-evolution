# Hacker News Submission Pack

> This file prepares titles, landing choices, and human talking points. It should not be pasted as an AI-generated HN comment. HN guidelines emphasize human conversation and discourage promotional behavior.

## Best First Submission

Title:

```text
Which AI agents actually self-improve?
```

URL:

```text
https://agent-evolution.com/projects/
```

Why this first:

- It is concrete and useful to developers.
- It avoids a generic "survey" framing.
- It invites disagreement and correction, which is healthy for an evidence atlas.
- It can point readers into search, graph, reports, and model cards.

## Strong Alternative

Title:

```text
The evaluation problem in self-evolving AI agents
```

URL:

```text
https://agent-evolution.com/blog/evaluation-benchmarks-for-self-evolving-agents/
```

Why:

- HN readers often respond better to bottleneck analysis than broad introductions.
- It critiques the field rather than promoting the site.
- It connects directly to benchmark quality, reproducibility, and reward hacking.

## Do Not Use As Show HN Yet

Avoid this for now:

```text
Show HN: A survey of self-evolving AI agents
```

Reason:

HN's Show HN guidelines say Show HN is for things users can try, and that blog posts, lists, newsletters, and pure reading material are off topic for Show HN.

## When Show HN Becomes Appropriate

Use Show HN only after the page foregrounds a tryable artifact:

- searchable evidence atlas
- interactive knowledge graph
- project scoring browser
- benchmark comparison explorer
- GitHub repo triage checklist

Possible title:

```text
Show HN: An evidence atlas for self-evolving AI agents
```

Best URL:

```text
https://agent-evolution.com/search/
```

## Human Comment Outline

If the submitter comments, keep it short and personal:

1. Why this was built: the field mixes real self-improvement, prompt iteration, agent frameworks, and hype.
2. What data is included: papers, GitHub projects, blogs/social signals, user pain points, benchmarks.
3. What feedback is wanted: missing projects, wrong classifications, better benchmark evidence.
4. What is incomplete: not every repo is deeply reviewed yet; some claims remain source-limited.

Do not ask for upvotes. Do not post generated comments verbatim.

## Submission Timing

Do not over-optimize timing. A useful technical artifact with a plain title matters more than launch theater. Submit when the landing page is fast, HTTPS works, source links are visible, and the author is available to answer questions.

## Checklist Before Posting

- [ ] `https://agent-evolution.com/` HTTPS certificate is valid without bypass.
- [ ] Landing page has source links and a clear "what this is" paragraph.
- [ ] Search works for `DGM`, `Reflexion`, `AlphaEvolve`, `SWE-Bench`.
- [ ] Project pages link back to original GitHub repos.
- [ ] Claims distinguish `[KNOWN]`, `[INFERRED]`, and `[UNVERIFIED]` where needed.
- [ ] Submitter can answer comments personally.
