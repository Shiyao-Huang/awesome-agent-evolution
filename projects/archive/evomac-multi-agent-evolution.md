## 1. 任务定义

EvoMAC 解决多智能体协作（MAC）网络在测试时的自适应进化问题：给定一个软件需求，如何动态调整智能体团队的组成（添加/删除智能体）和连接拓扑，使得协作网络能针对每个具体任务迭代优化？该问题的重要性在于将自进化从单智能体层面扩展到多智能体系统层面，并用客观环境反馈替代不可靠的自我评估。EvoMAC 还贡献了 rSDE-Bench——首个面向需求的软件开发基准，具有 99.22% 的人类评估相关性。

## 2. 方法核心

### 2.1 改进对象
可变状态为 MAC 网络 A = (V, E)：节点 V 是具有提示 p_i 的智能体，边 E 是任务依赖关系。进化同时修改智能体提示（节点属性）和工作流拓扑（边结构）。优化问题形式化为：min_{A_g} ⟨Φ(X, A_g), T⟩_E，其中 A_g 是编码网络，A_t 是测试网络。

### 2.2 变异算子 U
"文本反向传播"机制包含两个协作智能体：(1) 梯度智能体——分析执行日志产生"文本梯度"，对每个智能体识别子任务完成情况、错误引入和缺失子任务；(2) 更新智能体——根据文本梯度执行修改：删除已完成智能体、修正错误智能体的提示并附加建议方案、添加缺失子任务的新智能体，并基于新子任务依赖重构工作流拓扑。

### 2.3 适应度函数 V
测试团队生成单元测试作为目标代理，编译器执行代码产生客观环境反馈（执行日志）。消融实验表明，用 LLM 自我批评替代编译器导致 12-21% 的性能下降——客观环境反馈对可靠自进化至关重要。

### 2.4 选择机制 S
迭代式贪心进化：每轮进化根据环境反馈重构 MAC 网络，新网络直接替换旧网络。进化在测试时逐任务进行，每任务进行 3-5 轮迭代。无跨任务学习或知识迁移。

### 2.5 闭环结构
受神经网络训练启发的三阶段循环：(1) 前馈传播——自组织编码组织者分解需求为子任务并动态组装编码智能体团队；(2) 损失计算——测试团队生成单元测试，编译器执行提供客观反馈（执行日志）；(3) 反向传播——梯度智能体和更新智能体执行文本反向传播重构网络。三阶段循环重复直至收敛或达到迭代上限。

## 4. 定性判断

### 4.1 限制
- 依赖单元测试质量：测试不完整或与需求不一致会引导进化方向偏离
- 仅限于可验证任务：需要编译器等客观环境执行器，约束了向创意或开放式任务的扩展
- 无跨任务学习：每个任务独立进化，不保留已学到的网络结构，错失累积改进机会
- 计算成本：每轮进化涉及完整的编码、测试编译和文本反向传播，LLM API 成本成倍增加
- 驱动模型对比有限：主要使用 GPT-4o-Mini，其他模型族评估缺失
- 神经网络类比被批评为表面化：文本反向传播并非数学意义上的梯度计算或信用分配
- rSDE-Bench 任务（简单游戏和网站）可能不足以代表真实世界软件开发的挑战

### 4.2 适用场景
- 软件开发任务（具有编译器和单元测试的代码生成）
- 任何具有客观环境反馈的任务域
- 需要动态调整团队组成和工作流的场景
- 函数级和项目级编程任务的测试时优化
- 自动化软件工程流水线的自适应阶段

### 4.3 教学价值
- 多智能体系统的进化不限于单个智能体：可操作智能体网络的拓扑结构
- 客观环境反馈优于自我批评：12-21% 的消融性能下降提供了强有力的证据
- 文本反向传播（分析问题 -> 修复）是超越简单重试循环的干净抽象
- 测试时进化与训练时学习正交互补，结合两者可能产生乘法效应
- 自动评估基础设施是自进化研究的前提条件：rSDE-Bench 的贡献突出了这一点


EvoMAC 的 rSDE-Bench 贡献包含 616 个需求、53 个任务（覆盖 Game 和 Website 类型），具有 99.22% 的人类评估相关性。这一基准的价值在于为自进化研究提供了可靠的自动评估基础设施——没有客观反馈信号，自进化就不可靠。

EvoMAC 与 MetaGPT（固定瀑布流）、ChatDev（预定义角色）和 AutoGen（通用框架）的根本区别在于：前者动态重构智能体团队，后者使用固定的角色和拓扑。七种消融变体系统性地验证了每个组件的贡献（多智能体编码、多智能体测试、环境反馈、进化机制），提供了可靠的证据基础。

## 5. 与自进化的关系

EvoMAC 在 L1-L5 分类中属于 L3（多智能体网络结构进化）。其独特贡献是将进化对象从单智能体的代码或提示扩展到多智能体系统的拓扑结构 A = (V, E)。满足 (M)(U)(V)(S) 四要素，其中 V 强依赖客观环境反馈而非自我评估——这是区别于 Self-Rewarding 和 Meta-Rewarding 的关键设计选择。进化发生在测试时（per-task），与 RISE/RAGEN 的训练时方法正交。主要局限是缺乏跨任务的知识累积（每任务从零开始），但这也可以视为避免负迁移的安全特性。对自进化系统设计的核心启示是：任何自我进化系统都应优先选择环境接地的反馈而非自我评估。文本反向传播的"梯度-更新"分解提供了一种超越简单重试循环的通用架构。

计算方面，EvoMAC 使用 GPT-4o-Mini 和 Claude-3.5-Sonnet API 调用，成本主要由多轮进化迭代的 LLM 推理构成，无需 GPU 训练。

七种消融变体系统性地验证了每个组件的独立贡献，这是实验设计的一个亮点，为多智能体自进化系统的设计提供了可靠的经验指导。
