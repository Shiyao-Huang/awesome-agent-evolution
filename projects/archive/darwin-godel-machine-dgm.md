## 1. 任务定义

DGM 解决的核心问题是：智能体能否在不依赖人工设计的元智能体的前提下，通过修改自身的 Python 代码实现持续自我改进？该问题对自进化系统至关重要，因为它探索了自指式改进循环——下游任务性能的提升直接反馈到更强的自我修改能力上，形成复利增长。DGM 是首个消除了对手工元智能体依赖的自改进系统，实现了从固定架构搜索到开放式自指进化的范式转变。

## 2. 方法核心

### 2.1 改进对象
可变状态为智能体代码 A（Python 代码库），包括工具定义、上下文管理策略、代码编辑逻辑和控制流。底层 LLM 权重 θ 保持冻结。理论上，由于 Python 的图灵完备性，智能体可以表达任意可计算的修改。

### 2.2 变异算子 U
从存档中选择智能体变体，由 LLM 编辑其自身 Python 代码生成新变体。变异粒度覆盖整个代码库：工具函数、提示模板、控制流结构。变异不限于预设模板或受约束的搜索空间。系统自动发现了多种非显而易见的改进：更好的代码编辑工具、长上下文窗口管理策略、以及同行评审机制。

### 2.3 适应度函数 V
在编码基准（SWE-bench、Polyglot）上运行修改后的智能体，以任务完成率作为适应度。采用经验验证替代理论 Gödel Machine 的形式化证明要求，使系统在当前 LLM 技术下可行。

### 2.4 选择机制 S
维护开放式的智能体存档（受 quality-diversity 算法和 novelty search 启发），保留所有生成的变体而非仅保留最优者。选择同时考虑性能和多样性，鼓励并行探索不同的自我改进路径。存档中的每个变体都可以作为未来改进的起点，保留了进化中的垫脚石。

### 2.5 闭环结构
系统在两个阶段间交替运行：（1）自我修改阶段——存档中的智能体生成自身的修改版本，通过 LLM 编辑自身 Python 代码；（2）评估阶段——修改后的智能体在编码基准上测试，结果决定是否纳入存档。更好的编码性能带来更好的自我修改能力，形成正反馈循环。关键在于这是一种自指式改进：改进的对象（智能体代码）本身决定了改进的能力。

## 3. 定量证据

| 基准 | 基线 | 最佳 | 改进幅度 | 迭代次数 |
|---|---|---|---|---|
| SWE-bench | 20.0% | 50.0% | +30.0 pp | 多代进化 |
| Polyglot | 14.2% | 30.7% | +16.5 pp | 多代进化 |

30 个百分点的 SWE-bench 改进是实质性的，证明了该方法在编码智能体优化上的实际可行性。

## 4. 定性判断

### 4.1 限制
- 仅修改智能体代码（agent shell），不触及底层 LLM 权重，真正的自我改进需要修改模型参数
- 每次自我修改需要运行完整基准评估（如 SWE-bench），计算成本高昂
- 存档单调增长，长期存储和管理数千个智能体变体的可扩展性问题未解决
- 改进仅在编码基准上衡量，跨域泛化能力（数学、推理、创意任务）未验证
- 安全性方面：沙箱逃逸风险、自我修改不透明性、复合错误可能性
- 缺乏原则性的搜索策略，被社区批评为"把意大利面扔到墙上看看哪些能粘住"
- 自我修改可能在代码中引入难以察觉的微妙 bug，随迭代复合累积

### 4.2 适用场景
- 编码智能体的自动化架构搜索和自我优化
- 需要开放式探索而非单目标优化的研究场景
- 研究自指式改进循环的实验平台
- 具有客观评估指标的可验证任务域
- 沙箱环境中智能体架构的自动发现

### 4.3 教学价值
- 开放式存档方法的关键模式：保留多样性垫脚石而非仅保留最优解，这与 QD 算法的核心洞见一致
- Python 作为智能体自修改表示的实用选择：图灵完备且 LLM 理解良好
- "改进智能体代码"与"改进模型权重"之间的差距是当前自进化研究的根本性挑战
- 安全考虑必须从一开始就内置（沙箱、人类监督），而非事后添加
- 经验验证替代形式化证明是务实选择，但也移除了理论安全保证


与 ADAS（Hu et al., 2025）相比，DGM 的关键进步在于消除了固定元智能体——ADAS 使用手工设计的元智能体来优化其他智能体，而 DGM 让智能体自身成为优化器。与 Voyager（探索 Minecraft 技能）相比，DGM 探索的是自身代码的修改空间。与 AlphaEvolve（进化算法代码）相比，DGM 进化的是智能体架构本身。评估成本是 DGM 与其他方法共同的挑战：SWE-bench 每次评估耗时数分钟，限制了总进化代数。

在安全性方面，论文记录了沙箱和人类监督措施，但承认这些对于真正强大的系统可能不够。自我修改的不透明性（agent 以人类不易解读的方式修改自身代码）和复合错误风险（看似有益的修改可能引入随迭代累积的微妙 bug）是需要持续关注的安全问题。

## 5. 与自进化的关系

DGM 满足严格自进化的多个核心要素：(M) 可变状态为智能体代码 A；(U) LLM 驱动的代码变异；(V) 基准测试适应度；(S) 质量-多样性选择机制。在 L1-L5 分类中属于 L4（自指式智能体进化），因为智能体可以修改控制自身行为的代码。区别于 ADAS 的固定元智能体模式，DGM 消除了对手工元智能体的依赖——所有改进均由系统自身发现。关键局限在于进化对象是智能体壳（agent shell）而非 LLM 权重本身，这意味着 DGM 搜索的是智能体架构空间而非模型能力空间。其对未来自进化系统的核心启示是：开放式的多样性保留搜索比贪心选择更能发现非显而易见的改进路径，但评估成本是系统可扩展性的根本约束。与 AlphaEvolve 的 diff 式程序进化不同，DGM 的进化对象是智能体架构而非算法本身。

论文开源了代码（https://github.com/jennyzzt/dgm），计算需求显著但可复现。安全预防措施（沙箱、人类监督）有文档记录。DGM 的核心贡献不在于具体的基准分数，而在于证明了自指式改进循环的可行性——一个不断改进自身改进能力的系统。

DGM 的评估完全在客观基准（SWE-bench, Polyglot）上进行，避免了自我评估的循环性问题，但也将改进范围限制在编码领域。
