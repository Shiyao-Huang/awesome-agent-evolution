让 AI Agent 自己进化，但绝不放飞自我 —— 这个开源项目有点东西先说一个让我纠结了很久的问题 AI Agent - 掘金 # 让 AI Agent 自己进化，但绝不放飞自我 —— 这个开源项目有点东西 AI Agent 框架越来越多，OpenHands、OpenSpace、Evolver……每个都很酷。 但用了一段时间后，我发现一个尴尬的事： Agent 的能力不会随着使用而自动增长。 用了一个月，它还是刚部署时的样子。遇到相同的错误，它会重复踩坑。想给它加新能力，得手动改代码、写插件、配工作流。 说白了，还是“人驱动 Agent”，而不是“Agent 自己驱动自己”。 ## 直到我看到了 Evolver Evolver 提出了一个很酷的解法：让 AI 自己修改自己的“基因”。 但冷静下来一想 —— 你不知道它改了什么，也不知道能不能改回来。 对个人极客可能无所谓，但对想用在真实项目里的人（比如我）来说，这有点难接受。 ## 所以我自己写了一个 Self_Optimizing_Holo_Half (SOHH)，一个让 AI 系统像 App 一样持续迭代的自进化平台。 核心思路很简单：不追求让 AI 修改自己的源代码，而是构建一个 系统级的进化框架。 - 集成 OpenHands → 获得顶级的自动化开发能力 - 集成 OpenSpace → 获得基于技能的进化引擎 - 智能评分体系 → 6 个维度做 A/B 测试 - 版本管理 → 每次进化自动快照，一键回退 ## 它是怎么“进化”的？ 每天自动做三件事： 1. 抓资讯：拉取 OpenHands、OpenSpace 的 GitHub 动态 + AI 前沿论文 2. 分析：用大模型判断哪些更新能用上 3. 决策：A/B 测试 + 6 维评分 → 自动决定保留/回退 每次进化都会生成一份版本日志，清楚写着：建议来源、改了哪些文件、评估结果。 ## 双模式设计 - 自进化模式：完整进化流程，适合开发/测试 - 普通模式：只跑基础功能，适合生产环境 同一个项目，两种用法。 ## 和 Evolver 有什么不同？ | 维度 | Evolver | SOHH | | --- | --- | --- | | 进化信息来源 | 内部日志 | 外部资讯 + 用户行为 | | 进化对象 | Agent 的“基因” | 系统的功能模块 | | 透明度 | 黑盒 | 完全透明，有日志 | | 回退机制 | 无 | 一键回退 | 项目刚刚发布，代码可能还有粗糙的地方，但核心流程已经跑通。
