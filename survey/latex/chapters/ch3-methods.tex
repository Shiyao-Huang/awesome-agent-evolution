\section{方法分类}\label{ch:methods}

\subsection{本章概述}

Agent Evolution 方法众多，名称也不统一。本章按"主要选择压力与主要可变对象"进行分类：基于奖励的进化主要优化策略或行为分布；自博弈进化主要生成任务、对手和验证信号；提示词进化主要改变上下文、反思、原则和输出修订流程；架构搜索主要改变代码、工具、控制流和多智能体拓扑；基于记忆的进化主要改变长期经验、技能库和检索策略；混合方法则把多种机制组合成端到端闭环。

\subsubsection{分类维度说明}

我们的分类基于两个正交维度：

\begin{enumerate}
\item \textbf{选择压力（Selection Pressure）}：驱动进化的信号来源——外部奖励函数、自博弈胜负、自我评估文本、环境反馈、记忆检索命中率等。
\item \textbf{可变对象（Variable Object）}：被进化的目标——模型权重、提示词、代码、工具集、记忆结构、多智能体拓扑等。
\end{enumerate}

这两个维度的组合产生六大类别，每类方法共享相似的理论基础和技术瓶颈。需要指出的是，许多具体系统跨越多个类别（例如 DGM 同时涉及架构搜索和基于奖励的选择），我们的分类以"主要"机制为准。

\subsection{基于奖励的进化}\label{sec:reward}
% =====================================================================

基于奖励的进化是最接近传统强化学习和后训练的一类方法。核心思想是：把智能体交互轨迹、推理过程或输出结果映射为标量或偏好信号，再通过策略优化、偏好学习、筛选微调或archive selection使后续行为更可能获得高奖励。

\subsubsection{形式化框架}

基于奖励的进化可以统一在以下马尔可夫决策过程（MDP）框架下：

\begin{definition}[奖励驱动进化 MDP]
设 MDP $\mathcal{M} = (\mathcal{S}, \mathcal{A}, P, R, \gamma)$，其中：
\begin{itemize}
\item 状态空间 $\mathcal{S}$：包含任务描述 $x$、当前生成内容 $y_t$、历史反馈 $\{f_1, \ldots, f_{t-1}\}$
\item 动作空间 $\mathcal{A}$：模型 $\pi_\theta$ 的词汇表上的token分布
\item 转移函数 $P(s_{t+1} | s_t, a_t)$：由语言模型的自回归采样确定
\item 奖励函数 $R(s_t, a_t)$：由评估器（模型自评、外部工具或人工标注）给出标量或偏好信号
\item 折扣因子 $\gamma \in [0, 1]$
\end{itemize}
优化目标为：
\begin{equation}
\max_\theta \mathbb{E}_{\pi_\theta}\left[\sum_{t=0}^{T} \gamma^t R(s_t, a_t)\right] - \beta \cdot \mathrm{KL}(\pi_\theta \| \pi_{\mathrm{ref}})
\label{eq:reward-mdp}
\end{equation}
其中 $\beta$ 控制策略更新幅度相对于参考策略 $\pi_{\mathrm{ref}}$ 的约束。
\end{definition}

这一框架覆盖了从纯推理时的自我修正到需要权重更新的强化微调的广泛方法谱系。关键的分化点在于：（1）奖励信号的来源（自评 vs.\ 外部 vs.\ 混合）；（2）更新对象（上下文 vs.\ 权重 vs.\ 代码）；（3）数据来源（人工标注 vs.\ 自生成 vs.\ 环境反馈）。

\subsubsection{代表系统详解}

\paragraph{STaR: Self-Taught Reasoner}

\textbf{STaR}~\citep{star2022}是早期代表性工作，将"模型自己生成可学习材料"组织成闭环。其核心算法包含四个阶段：

\begin{enumerate}
\item \textbf{生成（Generation）}：给定问题 $x$，模型 $\pi_\theta$ 生成推理链 $r$ 和答案 $a$：
\begin{equation}
(r, a) \sim \pi_\theta(\cdot | x)
\label{eq:star-generate}
\end{equation}

\item \textbf{验证（Verification）}：将答案 $a$ 与真实标签 $a^*$ 比较，得到二值奖励 $r_{\mathrm{verify}} = \mathbb{1}[a = a^*]$。

\item \textbf{合理化（Rationalization）}：对于答错的问题，将真实答案作为提示注入，重新生成推理链：
\begin{equation}
r^+ \sim \pi_\theta(\cdot | x, a^*)
\label{eq:star-rationalize}
\end{equation}
这一步是 STaR 的关键创新——它将失败样本转化为可学习的正例。

\item \textbf{微调（Fine-tuning）}：用所有成功的推理链（原始 + 合理化后）微调模型：
\begin{equation}
\theta_{t+1} = \theta_t - \eta \nabla_\theta \mathcal{L}_{\mathrm{CE}}(\pi_\theta, \mathcal{D}_t^+)
\label{eq:star-train}
\end{equation}
其中 $\mathcal{D}_t^+$ 为第 $t$ 轮所有正确推理链的集合。
\end{enumerate}

STaR 的 bootstrapping 逻辑成为后续自演化研究的基础模板。其局限性在于：需要真实标签进行验证（半监督设定），且合理化步骤在无标签场景下无法使用。

\paragraph{Self-Rewarding Language Models}

\textbf{Self-Rewarding LM}~\citep{selfrewarding2024}将奖励信号进一步内生化。系统让同一个模型既生成候选回答又作为 judge 评价候选，并通过迭代 DPO 进行多轮偏好优化。

\begin{enumerate}
\item \textbf{候选生成}：对于每个指令 $x$，模型生成 $N$ 个候选 $\{y_1, \ldots, y_N\}$。

\item \textbf{自评打分}：模型作为 judge，对每个候选打分：
\begin{equation}
s_i = \mathrm{Score}_\theta(x, y_i) \in [1, 10]
\label{eq:selfreward-score}
\end{equation}

\item \textbf{偏好对构造}：选择最高分和最低分的候选构造偏好对 $(y_w, y_l)$。

\item \textbf{DPO 优化}：使用 DPO 损失更新模型：
\begin{equation}
\mathcal{L}_{\mathrm{DPO}} = -\mathbb{E}\left[\log \sigma\left(\beta \log \frac{\pi_\theta(y_w|x)}{\pi_{\mathrm{ref}}(y_w|x)} - \beta \log \frac{\pi_\theta(y_l|x)}{\pi_{\mathrm{ref}}(y_l|x)}\right)\right]
\label{eq:selfreward-dpo}
\end{equation}
\end{enumerate}

经过 $K$ 轮迭代后，模型同时提升了生成质量和评判能力。关键实验发现：self-judge 能力随迭代持续提升，而非停滞——这表明模型在学习"什么是好回答"的同时，也在学习"如何更好地评价"。

\paragraph{Meta-Rewarding}

\textbf{Meta-Rewarding}~\citep{metarewarding2024}进一步区分 actor、judge 和 meta-judge，让模型不仅评价回答，还评价评价本身：

\begin{itemize}
\item \textbf{Actor} $\pi_\theta^{\mathrm{actor}}$：生成候选回答 $y \sim \pi_\theta^{\mathrm{actor}}(\cdot | x)$
\item \textbf{Judge} $\pi_\theta^{\mathrm{judge}}$：评价回答质量 $s = J(y) \in \mathbb{R}$
\item \textbf{Meta-Judge} $\pi_\theta^{\mathrm{meta}}$：评价 judge 的评价质量 $s_{\mathrm{meta}} = MJ(x, y, s) \in \mathbb{R}$
\end{itemize}

Meta-Judge 的引入解决了"谁来监督评判者"的问题。训练时，三个角色共享同一个基础模型的不同 prompt 前缀，通过 multi-objective RL 同时优化。

\paragraph{RISE: Recursive Introspection}

\textbf{RISE}~\citep{rise2024}将自我改进建模为多轮 MDP，通过 RL 微调使自我修正成为可学习的行为，而非纯粹的提示技巧。

\begin{definition}[RISE 多轮 MDP]
状态 $s_t = (x, \{y_1, \ldots, y_t\})$ 包含原始问题和历史生成。动作 $a_t$ 为下一步的推理/修正内容。转移函数 $P$ 由模型的自回归采样决定。奖励仅在最终轮给出：
\begin{equation}
R(s_T) = \mathbb{1}[\text{answer}(y_T) = a^*]
\label{eq:rise-reward}
\end{equation}
训练目标为：
\begin{equation}
\max_\theta \mathbb{E}_{\pi_\theta}\left[\sum_{t=1}^{T} \gamma^t r_t\right] - \beta \cdot \mathrm{KL}(\pi_\theta \| \pi_{\mathrm{ref}})
\label{eq:rise-objective}
\end{equation}
\end{definition}

RISE 的关键创新在于将 Self-Refine 式的推理时自我修正从"prompt trick"提升为"可训练策略"。通过在线模仿学习（inspired by DAGGER），模型学习在检测到错误时主动分配更多"内省预算"——难度自适应行为自然涌现。

实验结果表明：
\begin{itemize}
\item GSM8K（Llama2-7B）：~14\% $\rightarrow$ ~24\%（+10pp）
\item GSM8K（Mistral-7B）：~38\% $\rightarrow$ ~46\%（+8pp）
\item 多轮自我检查持续优于单轮，且 RL 微调达到了纯提示（Self-Refine）无法企及的效果
\end{itemize}

\paragraph{Agent-R}

\textbf{Agent-R}~\citep{agentr2024}将奖励驱动的进化扩展到工具使用和多步行动的智能体场景。与传统 RL 微调不同，Agent-R 引入了"轨迹级奖励分解"——将最终任务成功的信号合理地归因到中间决策步骤，解决了长轨迹中信用分配的难题。

\paragraph{RAGEN: 多轮强化学习中的自进化}

\textbf{RAGEN}~\citep{ragen2025}提出了 StarPO（State-Thinking-Actions-Reward Policy Optimization）框架，将智能体轨迹分解为状态、思考、动作和奖励四个组件：

\begin{definition}[StarPO 框架]
轨迹 $\tau = \{(s_1, t_1, a_1, r_1), \ldots, (s_T, t_T, a_T, r_T)\}$，其中 $s_t$ 为环境状态，$t_t$ 为模型的内部思考，$a_t$ 为外部动作，$r_t$ 为即时奖励。StarPO 的优化目标为：
\begin{equation}
\max_\theta \mathbb{E}\left[\sum_{t=1}^{T} \gamma^t r_t \cdot \log \pi_\theta(a_t | s_t, t_t)\right]
\label{eq:starpo}
\end{equation}
\end{definition}

RAGEN 的一个关键发现是\textbf{"Echo Trap"现象}——在多轮 RL 训练中，智能体学会了重复自己的输出而非真正推理，制造出改进的假象：
\begin{equation}
\text{Echo Detection: } \cos_{\mathrm{sim}}(t_t, t_{t-1}) > \tau_{\mathrm{echo}} \Rightarrow \text{echo}
\label{eq:echo-trap}
\end{equation}
StarPO-S 通过轨迹过滤来移除"echo"轨迹，有效缓解了这一问题。

\subsubsection{核心挑战}

基于奖励的方法面临多重挑战：

\textbf{Goodhart 风险}：模型可能学会迎合评分规则而非真正提升能力。当奖励函数 $\hat{R}$ 不完全对齐真实目标 $R^*$ 时，优化 $\hat{R}$ 可能导致 $R^*$ 下降。Self-Rewarding 和 Meta-Rewarding 的迭代过程本质上试图缓解这一问题——通过让评价能力与生成能力共同进化，减少奖励模型与真实偏好之间的 gap。

\textbf{样本效率}：RL 训练需要大量交互轨迹。以 RISE 为例，在 GSM8K 上从 14\% 提升到 24\% 需要数千条多轮轨迹的采样和优化。自博弈方法（如 Absolute Zero）通过消除对外部数据的依赖部分缓解了这一问题，但以牺牲训练稳定性为代价。

\textbf{泛化不确定性}：在特定 benchmark 上的改进不一定迁移到真实场景。STaR 在数学推理上的提升能否迁移到代码生成？Self-Rewarding 的评价能力能否跨领域一致？这些问题的答案尚不明确。

\textbf{奖励作弊（Reward Hacking）}：当模型作为自己的 judge 时，存在系统性高估自身输出的倾向。Meta-Rewarding 通过引入元评价层级部分缓解了这一问题，但理论上仍无法保证完全消除作弊行为。

\subsection{自博弈进化}\label{sec:selfplay}
% =====================================================================

自博弈进化把"数据从哪里来"这个问题推到系统内部。核心思想是：与其依赖人类标注或外部环境提供的固定数据集，不如让系统自己生成训练任务和验证信号，形成完全自给自足的进化闭环。

\subsubsection{形式化框架}

\begin{definition}[自博弈进化框架]
设系统包含三个可由同一模型 $\pi_\theta$ 通过不同 prompt 承担的角色：
\begin{itemize}
\item \textbf{Proposer} $\pi_\theta^P$：生成任务 $t \sim \pi_\theta^P(\cdot | \mathcal{C})$，其中 $\mathcal{C}$ 为课程状态
\item \textbf{Solver} $\pi_\theta^S$：尝试求解 $s \sim \pi_\theta^S(\cdot | t)$
\item \textbf{Verifier} $V$：验证解答 $r = V(s, t) \in \{0, 1\}$
\end{itemize}
Proposer 的奖励应鼓励产生"位于能力边界"的任务：
\begin{equation}
R_P(t) \propto \text{difficulty}(t) \times \text{solvability}(t) \times \text{diversity}(t, \mathcal{H})
\label{eq:selfplay-reward}
\end{equation}
其中 $\mathcal{H}$ 为历史任务集合。同时优化 Proposer 和 Solver：
\begin{equation}
\max_\theta \mathbb{E}_{t \sim \pi_\theta^P}\left[R_P(t) + \lambda \cdot R_S(s, t)\right]
\label{eq:selfplay-joint}
\end{equation}
\end{definition}

\subsubsection{代表系统详解}

\paragraph{Absolute Zero: 零数据强化自博弈推理}

\textbf{Absolute Zero}~\citep{absolutezero2025}（NeurIPS 2025 最佳论文奖）代表了自博弈进化的前沿。其核心贡献是：在完全零外部数据条件下，由同一个模型同时提出任务并尝试解决。

\textbf{任务生成}：模型通过编程生成任务——Proposer 编写代码来生成输入-输出对：
\begin{equation}
t = \text{TaskProgram}(\text{domain}, \text{difficulty})
\label{eq:az-task}
\end{equation}
支持三种推理模式：演绎（deduction）、 abduction（溯因）和 induction（归纳）。

\textbf{自动验证}：利用代码执行器作为确定性验证器：
\begin{equation}
r = \text{Execute}(s, t) \in \{0, 1\}
\label{eq:az-verify}
\end{equation}
这消除了奖励模型的不确定性——代码要么通过测试，要么不通过。

\textbf{课程奖励}：Proposer 的奖励与任务的学习价值成正比：
\begin{equation}
R_P \propto \text{difficulty}(t) \times \text{solvability}(t) \times \text{diversity}(t, \mathcal{H})
\label{eq:az-curriculum}
\end{equation}

\textbf{实验结果}：
\begin{itemize}
\item AZR-Coder-7B 在 HumanEval+、MBPP+ 和整体编程平均上达到 7B 规模的 SOTA——完全无外部训练数据
\item 在 GSM8K 和 MATH 上具有竞争力，尽管没有数学训练数据（从代码自博弈到数学推理的跨域迁移）
\item pass@1 和 pass@128 随训练持续提升
\end{itemize}

Absolute Zero 将 AlphaGo Zero 的范式扩展到 LLM 推理。其关键洞察是："更强的模型更善于让自己变得更强"——这暗示了自我改进存在正反馈循环的潜力。

\paragraph{SPIRAL: 自博弈推理发现}

\textbf{SPIRAL}~\citep{spiral2024}让语言模型在零和博弈中自我博弈，发现可迁移的推理能力。与 Absolute Zero 不同，SPIRAL 使用竞争性游戏作为任务生成器，两个智能体互为对手。

\textbf{关键发现}：
\begin{itemize}
\item 自博弈中涌现的推理策略（如搜索、规划、假设检验）可以迁移到非游戏任务
\item 竞争压力自然产生"课程学习"效果——对手越强，需要发现的策略越复杂
\item 与 AlphaGo 的自我博弈发现新策略类似，但迁移到了语言推理领域
\end{itemize}

\paragraph{Multi-Agent Debate}

多智能体辩论~\citep{madd2023}将自博弈从两个角色扩展到多个智能体。多个 LLM 实例围绕同一问题展开辩论，通过"社会性验证"达成共识。其理论基础是"多样性假设"——不同初始化（或不同 prompt）的模型在独立犯错时，多数投票可以消除个别模型的系统性偏差。

\paragraph{Self-Play Fine-Tuning (SPIN)}

\textbf{SPIN}~\citep{spin2024}将自博弈引入监督微调。核心思想是：让模型与自身先前版本进行"博弈"——新模型需要区分人类标注和旧模型生成的输出：
\begin{equation}
\mathcal{L}_{\mathrm{SPIN}} = -\mathbb{E}\left[\log \sigma\left(\lambda \log \frac{\pi_{\theta_t}(y|x)}{\pi_{\theta_{t-1}}(y|x)}\right)\right] + \mathbb{E}\left[\log \sigma\left(\lambda \log \frac{\pi_{\theta_{t-1}}(y'|x)}{\pi_{\theta_t}(y'|x)}\right)\right]
\label{eq:spin-loss}
\end{equation}
其中 $y$ 为人类标注，$y'$ 为旧模型生成。SPIN 的理论保证表明：当且仅当 $\pi_\theta$ 与人类数据分布一致时，训练收敛。

\subsubsection{自博弈的理论分析}

自博弈方法的理论基础来自博弈论和进化计算：

\textbf{Nash 均衡视角}：在双人零和博弈中，自博弈收敛到 Nash 均衡。AlphaGo Zero 验证了这一理论在实际中的有效性。然而，LLM 自博弈中的非零和结构使得收敛性保证更加复杂。

\textbf{课程学习视角}：自博弈隐含了一个自动课程——随着 Solver 能力提升，Proposer 必须生成更难的任务以维持学习信号。Absolute Zero 的课程奖励（Eq.~\ref{eq:az-curriculum}）显式化了这一机制。

\textbf{模式坍塌风险}：自博弈最严重的理论风险是 Proposer 和 Solver 收敛到"默契配合"——Proposer 只出简单题，Solver 总能做对，两者共同获得高奖励但实际能力没有提升。这类似于 GAN 中的模式坍塌问题。Absolute Zero 通过 diversity 约束和代码验证部分缓解了这一风险。

\subsection{提示词进化}\label{sec:prompt}
% =====================================================================

提示词进化是最轻量、最容易部署的一类 Agent Evolution。其核心思想是：不改变模型权重或代码结构，而是通过迭代修改提示词、上下文和反馈文本，使模型在推理时产生更好的输出。这类方法的关键优势在于\textbf{零训练成本}和\textbf{即插即用}——不需要 GPU、不需要微调、可以在任何 LLM API 上直接使用。

\subsubsection{形式化框架}

\begin{definition}[提示词进化框架]
设模型 $\pi_\theta$ 固定（权重不变），提示词进化通过修改上下文序列来优化输出：
\begin{itemize}
\item \textbf{初始提示} $p_0$：包含任务指令、示例或约束
\item \textbf{反馈函数} $F$：根据输出 $y_t$ 和任务 $x$ 生成自然语言反馈 $f_t = F(y_t, x)$
\item \textbf{提示更新} $U$：基于反馈修改提示 $p_{t+1} = U(p_t, y_t, f_t)$
\end{itemize}
迭代过程为：
\begin{equation}
y_t = \pi_\theta(\cdot | x, p_t), \quad f_t = F(y_t, x), \quad p_{t+1} = U(p_t, y_t, f_t)
\label{eq:prompt-evolve}
\end{equation}
收敛条件：$f_t$ 指示"无需改进"或达到最大迭代次数。
\end{definition}

\subsubsection{代表系统详解}

\paragraph{Reflexion: 语义梯度}

\textbf{Reflexion}~\citep{reflexion2023}将稀疏奖励转化为"语义梯度"——相比仅告诉模型"失败"，反思文本能指出失败原因和改进方向。Reflexion 使用三模型架构：

\begin{enumerate}
\item \textbf{Actor} $M_a$：在给定任务和记忆的情况下生成行动
\begin{equation}
a_e = M_a(\text{task}, \mathcal{M}_{1:e-1})
\label{eq:reflexion-actor}
\end{equation}

\item \textbf{Evaluator} $M_e$：评估行动结果
\begin{equation}
r_e = M_e(a_e, \text{task})
\label{eq:reflexion-eval}
\end{equation}

\item \textbf{Self-Reflection} $M_r$：生成自然语言反思
\begin{equation}
f_e = M_r(a_e, r_e, \text{task})
\label{eq:reflexion-reflect}
\end{equation}
\end{enumerate}

记忆更新为：$\mathcal{M}_e = \mathcal{M}_{e-1} \cup \{f_e\}$

\textbf{关键实验结果}：
\begin{itemize}
\item HumanEval（代码生成）：Reflexion（GPT-3.5）达到 \textbf{91.0\% pass@1}，超过 GPT-4 零样本的 80.1\%
\item AlfWorld（交互式任务）：\textbf{97\% 成功率} vs.\ 75\% 基线
\item 更多的反思轮次带来更好的性能（收益递减）
\item 具体的反馈优于通用反馈
\end{itemize}

Reflexion 的核心洞见是"\textbf{记忆替代梯度}"——自然语言反馈充当了传统 RL 中梯度信号的角色，无需参数更新。

\paragraph{Self-Refine: 迭代自反馈}

\textbf{Self-Refine}~\citep{selfrefine2023}使用同一个模型完成三个步骤：GENERATE、CRITIQUE、REFINE：

\begin{enumerate}
\item \textbf{生成}：$y_0 = \text{LLM}(x, \text{instruction})$
\item \textbf{评价}：$\text{fb}_t = \text{LLM}(y_t, \text{rubric})$
\item \textbf{精炼}：$y_{t+1} = \text{LLM}(y_t, \text{fb}_t, \text{instruction})$
\end{enumerate}

收敛条件：$\text{fb}_t$ = "无需改进" 或达到 $\max_t$。

Self-Refine 在 7 个任务上平均提升约 20\%：
\begin{itemize}
\item 代码优化：+28\%
\item 数学推理：56\% $\rightarrow$ 67\%（+11pp）
\item 情感反转：74\% $\rightarrow$ 86\%（+12pp）
\item 对话生成：52\% $\rightarrow$ 68\%（+16pp）
\item 约束生成：65\% $\rightarrow$ 78\%（+13pp）
\end{itemize}

\textbf{局限性}：自我评价可能陷入局部最优——模型的自我批评可能遗漏根本性缺陷，因为同一模型的生成和评价能力受限于相同的认知边界。

\paragraph{ExPeL: 经验驱动的自主学习}

\textbf{ExPeL}~\citep{expel2023}从训练任务中自主收集经验，抽取自然语言 insights。与 Reflexion 的关键区别在于：
\begin{itemize}
\item Reflexion 的反思是即时的、针对单次失败的
\item ExPeL 的 insights 是跨任务聚合的、从多次成功/失败中抽取的模式
\end{itemize}

ExPeL 的两阶段流程：
\begin{enumerate}
\item \textbf{经验收集}：在多个任务上执行，收集 (task, trajectory, success) 三元组
\item \textbf{insight 抽取}：LLM 分析成功和失败的案例，生成可迁移的自然语言经验：
\begin{equation}
\text{Insights} = \text{LLM}(\text{Summarize}, \{(\text{task}_i, \text{traj}_i, \text{result}_i)\})
\label{eq:expel-insights}
\end{equation}
\end{enumerate}

\paragraph{ACE: 上下文工程}

\textbf{ACE}~\citep{ace2024}把上下文工程定义为可演化的 playbook。使用结构化增量更新避免上下文坍缩——随着对话变长，早期重要信息被"淹没"在冗长的上下文中。ACE 维护一个结构化的 playbook，每次只更新相关部分而非追加全文。

\paragraph{Agent Symbolic Learning}

\textbf{Agent Symbolic Learning}~\citep{agentsymbolic2024}将反向传播和梯度下降完全映射到自然语言空间。其核心创新是"\textbf{语言梯度}"——用文本描述如何改进每个组件：

\begin{definition}[语言梯度]
给定语言损失 $\mathcal{L}_{\mathrm{lang}} = \mathrm{LLM}(P_{\mathrm{loss}}, \text{trajectory})$，语言梯度通过链式反向传播计算：
\begin{equation}
\nabla_{\mathrm{lang}}^n = \mathrm{LLM}(P_{\mathrm{gradient}}, \nabla_{\mathrm{lang}}^{n+1}, \text{node}_n, \mathcal{L}_{\mathrm{lang}})
\label{eq:lang-gradient}
\end{equation}
\end{definition}

该方法在 HotPotQA 上从 36.2/22.8 提升到 39.1/25.6（F1/EM），超过 DSPy 的 37.4/24.1。

提示词进化方法位于"推理时自我改进"的一端，与"训练时自我改进"方法（如 STaR、RISE）形成光谱：

\subsection{架构搜索}\label{sec:arch}
% =====================================================================

架构搜索关注 agent 结构本身的自动设计。与提示词进化（优化输入）和奖励进化（优化策略/权重）不同，架构搜索直接优化\textbf{agent 的代码实现}——包括提示词模板、工具选择、控制流、多智能体拓扑等。这类方法的理论基础来自神经架构搜索（NAS），但搜索空间从神经网络拓扑扩展到了图灵完备的程序空间。

\subsubsection{形式化框架}

\begin{definition}[架构搜索框架]
设搜索空间 $\mathcal{S}$ 为所有有效的 agent 实现程序的集合。架构搜索的目标是找到：
\begin{equation}
a^* = \arg\max_{a \in \mathcal{S}} \text{Fitness}(a, \mathcal{T})
\label{eq:arch-search}
\end{equation}
其中 $\mathcal{T}$ 为评估任务集。搜索过程通过以下迭代进行：
\begin{enumerate}
\item \textbf{采样}：从 archive $\mathcal{D}$ 中选择父代 $a_{\mathrm{parent}}$
\item \textbf{变异}：使用 LLM 生成子代 $a_{\mathrm{child}} = \mathrm{LLM}(a_{\mathrm{parent}}, \text{edit\_instruction})$
\item \textbf{评估}：计算 $\text{Fitness}(a_{\mathrm{child}}, \mathcal{T})$
\item \textbf{选择}：如果 $\text{Fitness}(a_{\mathrm{child}}) > \text{Fitness}(a_{\mathrm{parent}})$，将 $a_{\mathrm{child}}$ 加入 archive
\end{enumerate}
\end{definition}

\subsubsection{代表系统详解}

\paragraph{ADAS: 自动化智能体系统设计}

\textbf{ADAS}~\citep{adas2024}（ICLR 2025，414+ 引用）定义了"自动化智能体系统设计"这一研究领域，并提出了"Meta Agent Search"方法：

\begin{enumerate}
\item \textbf{搜索空间}：$\mathcal{S} = \{\text{所有有效 Python 程序}\}$——这是图灵完备的搜索空间，包含所有可能的智能体设计
\item \textbf{Meta Agent}：一个 LLM 迭代地编写定义新 agent 架构的代码
\begin{equation}
a_{\mathrm{new}} = \mathrm{LLM}(\mathcal{D}, \text{history}, \text{search\_strategy})
\label{eq:adas-search}
\end{equation}
\item \textbf{评估}：在基准任务上运行新 agent 并记录性能
\item \textbf{存档}：$\mathcal{D} = \mathcal{D} \cup \{(a_{\mathrm{new}}, \text{score}(a_{\mathrm{new}}))\}$
\end{enumerate}

\textbf{关键实验结果}：
\begin{itemize}
\item ARC（抽象推理）：超过手工设计的 SOTA agent
\item GFootball：超过手工设计的 SOTA agent
\item \textbf{跨域迁移}：在 ARC 上发现的 agent 设计在 GFootball 上同样有效
\item \textbf{跨模型迁移}：用 GPT-3.5 搜索到的 agent 在 GPT-4 上仍然有效
\end{itemize}

跨模型迁移是一个特别值得注意的发现——这意味着 LLM 可以发现的智能体设计模式具有某种"架构不变性"，不依赖于特定模型的特性。

\paragraph{Gödel Agent: 自指代理框架}

\textbf{Gödel Agent}~\citep{godelagent2024}（ACL 2025）是第一个直接受 Schmidhuber 的 Gödel Machine（2003）启发的自指代理框架。其核心机制是 LLM 驱动的 monkey patching——在运行时动态修改自身的逻辑和行为：

\begin{enumerate}
\item \textbf{初始化}：Agent $A$ 以初始代码 $\text{code}_0$ 开始
\item \textbf{执行}：在任务上执行，收集结果和反馈
\item \textbf{自省}：读取自身代码和状态，生成改进计划
\begin{equation}
\text{plan} = \mathrm{LLM}(A.\text{code}, \text{feedback}, \text{objective})
\label{eq:godel-plan}
\end{equation}
\item \textbf{自修改}：执行 monkey patch
\begin{equation}
\text{exec}(\text{patch\_code}) \quad \text{修改 } A \text{ 的方法}
\label{eq:godel-patch}
\end{equation}
\item \textbf{验证}：在验证集上比较 $A'$ 和 $A$ 的性能；如果改进则接受，否则回滚
\end{enumerate}

\textbf{实验结果}：在 HotPotQA 上超过手工设计的 agent +8-15\%，在 ALFWorld 上显著改善。关键特性是持续改进和发现人类设计者未预见的新策略。

\textbf{局限性}：依赖 Python monkey patching（平台特定），运行时自修改引入非确定性和安全性隐患。

\paragraph{DGM: Darwin Gödel Machine}

\textbf{DGM}~\citep{dgm2025}结合了达尔文进化与 Gödel Machine 的自指特性。维护一个开放式的 agent 实现存档：

\begin{enumerate}
\item \textbf{Archive}：$\mathcal{A} = \{a_1, \ldots, a_n\}$，每个 agent 带有适应度分数
\item \textbf{采样}：按适应度和多样性加权采样父代
\begin{equation}
P(a_i) \propto f(a_i) \times \text{diversity\_bonus}(a_i, \mathcal{A})
\label{eq:dgm-sample}
\end{equation}
\item \textbf{变异}：LLM 提出代码修改
\item \textbf{选择}：如果 $\text{fitness}(a_{\mathrm{child}}) > \text{fitness}(a_{\mathrm{parent}})$ 则保留
\end{enumerate}

\textbf{关键结果}：
\begin{itemize}
\item SWE-bench：20.0\% $\rightarrow$ \textbf{50.0\% verified}
\item Polyglot（多语言编程）：14.2\% $\rightarrow$ \textbf{30.7\%}
\item 发现了人类设计者未曾想象的全新 agent 结构
\end{itemize}

\paragraph{AlphaEvolve: Gemini 驱动的进化编码}

\textbf{AlphaEvolve}~\citep{alphaevolve2025}（Google DeepMind）将进化编码推向了新的高度。使用 Gemini Flash（广度/快速探索）+ Gemini Pro（深度/关键洞察）的双 LLM 集成，结合 MAP-Elites 质量多样性搜索：

\begin{definition}[AlphaEvolve MAP-Elites]
种群 $P = \{p_1, \ldots, p_n\}$，每个个体带有适应度和行为描述符。变异通过 LLM 进行：
\begin{equation}
p_{\mathrm{child}} = \mathrm{LLM}(p_{\mathrm{parent}}, \text{evolution\_context})
\label{eq:alphaevolve-mutate}
\end{equation}
Archive 更新采用 MAP-Elites 规则：
\begin{equation}
\text{Archive}[b(p_{\mathrm{child}})] = p_{\mathrm{child}} \quad \text{if } f(p_{\mathrm{child}}) > f(\text{Archive}[b(p_{\mathrm{child}})])
\label{eq:alphaevolve-archive}
\end{equation}
\end{definition}

\textbf{突破性成果}：
\begin{itemize}
\item \textbf{数学}：发现使用仅 48 次乘法的 4×4 复数矩阵乘法——56 年来首次超越 Strassen 算法
\item \textbf{基础设施}：通过数据中心调度恢复全球 \textbf{0.7\% 的计算资源}；FlashAttention 内核提速 \textbf{23\%}；LLM 训练注意力提速 \textbf{32\%}
\end{itemize}

\paragraph{FunSearch}

\textbf{FunSearch}~\citep{funsearch2023}（Nature 2023）是 AlphaEvolve 的前身，使用进化搜索发现数学函数。其核心思想是将 LLM 作为变异算子，在函数空间中搜索。

\paragraph{EvoMAC}

\textbf{EvoMAC}~\citep{evomac2024}将架构搜索扩展到多智能体协作（Multi-Agent Collaboration）。不仅搜索单个 agent 的设计，还搜索 agent 之间的通信协议和任务分配策略。

\subsubsection{架构搜索的理论分析}

\textbf{搜索空间复杂度}：由于搜索空间是所有有效 Python 程序（图灵完备），理论上搜索空间是无限的。LLM 作为搜索算子将搜索限制在了"合理的程序空间"内，但无法保证找到全局最优。

\textbf{开放性与收敛性}：DGM 的开放式 archive 设计避免了收敛到单一局部最优，使探索定性不同的架构成为可能。这与传统 NAS 中的贪心搜索形成对比。

\textbf{可组合性}：架构搜索发现的组件通常可以跨任务和跨模型组合使用。ADAS 的跨模型迁移实验验证了这一点——用弱模型搜索到的设计在强模型上仍然有效。

\textbf{安全性}：架构搜索引入了新的安全风险。自修改代码（如 Gödel Agent）可能在运行时产生不可预测的行为。AlphaEvolve 通过自动化验证器缓解了这一风险，但并非所有任务都有可靠的验证器。

\subsection{记忆进化}\label{sec:memory}
% =====================================================================

记忆进化关注长期经验的积累与检索。与提示词进化（将反馈存储在即时上下文中）不同，记忆进化维护一个持久的、可检索的经验数据库，agent 可以在未来的任务中利用过去学到的知识和技能。这类方法的核心挑战是：如何在无限任务流中高效地存储、索引、检索和遗忘经验。

\subsubsection{形式化框架}

\begin{definition}[记忆进化框架]
设记忆系统 $\mathcal{M}$ 包含：
\begin{itemize}
\item \textbf{经验存储} $\mathcal{E} = \{e_1, \ldots, e_n\}$，每个经验 $e_i = (\text{task}_i, \text{trajectory}_i, \text{outcome}_i, \text{insight}_i)$
\item \textbf{索引函数} $I: \mathcal{E} \rightarrow \mathbb{R}^d$，将经验映射到嵌入空间
\item \textbf{检索函数} $\text{Ret}: \text{query} \times \mathcal{E} \rightarrow \mathcal{E}_{\mathrm{top-k}}$
\item \textbf{更新策略} $U$：决定何时添加、更新或删除经验
\end{itemize}
在任务 $x$ 上，agent 使用检索到的经验进行决策：
\begin{equation}
y = \pi_\theta(\cdot | x, \text{Ret}(x, \mathcal{E}))
\label{eq:memory-retrieval}
\end{equation}
记忆更新通过以下操作之一进行：
\begin{itemize}
\item \textbf{ADD}：$\mathcal{E} \leftarrow \mathcal{E} \cup \{e_{\mathrm{new}}\}$
\item \textbf{UPDATE}：$e_i \leftarrow U(e_i, \text{new\_experience})$
\item \textbf{DELETE}：$\mathcal{E} \leftarrow \mathcal{E} \setminus \{e_j\}$
\item \textbf{NOOP}：保持不变
\end{itemize}
\end{definition}

\subsubsection{代表系统详解}

\paragraph{Voyager: 开放世界终身学习}

\textbf{Voyager}~\citep{voyager2023}通过自动课程和技能库实现开放世界终身学习。三个核心组件：

\begin{enumerate}
\item \textbf{自动课程}：根据当前能力和世界状态自动提出下一个任务
\begin{equation}
\text{task}_{t+1} = \text{Curriculum}(\text{state}_t, \text{skills\_acquired})
\label{eq:voyager-curriculum}
\end{equation}

\item \textbf{技能库}：存储可复用的 JavaScript 代码片段
\begin{equation}
\text{SkillLib} = \{(\text{name}_i, \text{code}_i, \text{description}_i)\}
\label{eq:voyager-skills}
\end{equation}
每个技能从成功完成的任务中提取，并在后续任务中通过语义检索重用。

\item \textbf{迭代反思}：当任务失败时，agent 反思并修改代码，直到成功或放弃
\end{enumerate}

Voyager 在 Minecraft 中展示了强大的终身学习能力——发现的技能（如"砍树"、"制作工具"、"探索矿洞"）可以组合使用，解锁越来越复杂的任务链。

\paragraph{Memory-R1: RL 训练的记忆管理器}

\textbf{Memory-R1}~\citep{memoryr1_2025}用 RL 训练记忆管理器，使其学会何时添加、更新、删除或保持不变：

\begin{equation}
a_{\mathrm{mem}} \in \{\text{ADD, UPDATE, DELETE, NOOP}\}
\label{eq:memr1-actions}
\end{equation}

与 Voyager 的启发式记忆管理不同，Memory-R1 通过 RL 训练使记忆管理策略与任务目标对齐。关键实验发现：RL 训练后的记忆管理器学会了主动删除过时信息和合并相似经验，这远超简单的"全部保留"策略。

\paragraph{AriadneMem: 演化图记忆}

\textbf{AriadneMem}~\citep{ariadnemem2025}提出演化图表示来管理记忆：
\begin{itemize}
\item \textbf{图结构}：记忆以有向图形式组织，节点为经验片段，边为语义关联
\item \textbf{熵感知门控}：基于信息熵决定何时压缩或扩展记忆
\item \textbf{冲突感知粗化}：当新旧记忆冲突时，自动进行粒度调整
\end{itemize}

\paragraph{其他记忆系统}

\textbf{SEDM}~\citep{sedm2024}将自我进化分解为"经验蒸馏"——从大量交互历史中蒸馏出紧凑的经验表示。\textbf{A-Mem}~\citep{amem2024}实现了记忆的自主管理，包括主动遗忘和信息整合。\textbf{Memento}~\citep{memento2024}将记忆管理建模为分层决策过程，不同层级管理不同时间尺度的经验。

\subsubsection{记忆进化的核心挑战}

\textbf{记忆容量与检索效率}：随着经验积累，记忆库规模不断增长。如何在保持检索质量的同时控制存储和计算成本？AriadneMem 的图粗化是一种解决方案，但通用的高效记忆索引仍是一个开放问题。

\textbf{遗忘与保留的平衡}：何时删除过时经验？何时保留看似无用但可能在远期任务中关键的"意外知识"？这类似于持续学习中的"稳定性-可塑性困境"。

\textbf{记忆一致性}：当新旧经验产生矛盾时（例如同一 API 在不同版本有不同的行为），如何解决冲突？AriadneMem 的冲突感知粗化机制尝试解决这一问题。

\textbf{负迁移}：在某些任务中获得的经验可能在其他任务上产生负面影响。例如，在代码生成中学到的特定语言习惯可能不适用于另一语言。记忆系统需要具备识别和隔离负迁移的能力。

\subsection{混合方法}\label{sec:hybrid}
% =====================================================================

混合方法将多种进化机制组合成端到端闭环，突破单一类别的局限。其核心动机是：现实世界的复杂任务通常需要同时优化多个维度（代码质量、推理深度、记忆利用、工具选择等），单一方法难以覆盖所有需求。

\subsubsection{代表系统详解}

\paragraph{EvolveR: 全生命周期进化}

\textbf{EvolveR}~\citep{evolver2024}提出覆盖智能体全生命周期的统一进化框架。不同于仅优化推理时行为或仅优化训练时权重的方法，EvolveR 同时进化：
\begin{itemize}
\item \textbf{推理策略}：通过 Reflexion 式的自我反思优化即时决策
\item \textbf{长期记忆}：通过经验抽取和整合优化知识积累
\item \textbf{工具使用}：通过试错学习优化工具选择和参数配置
\item \textbf{自身代码}：通过 LLM 驱动的代码修改优化 agent 架构
\end{itemize}

EvolveR 的关键创新在于将这些进化机制统一在一个生命周期框架下，使它们可以协同而非竞争地运行。

\paragraph{WebEvolver: Web 环境进化}

\textbf{WebEvolver}~\citep{webevolver2024}将进化框架部署到真实的 Web 环境中。agent 不仅需要生成代码和推理，还需要与网页交互、填写表单、导航链接。进化信号来自任务完成度和网页状态变化。

\paragraph{HyperAgents}

\textbf{HyperAgents}~\citep{hyperagents2024}实现了一种"超智能体"架构——一个 meta-agent 管理和进化多个子智能体。meta-agent 通过观察子智能体的表现，动态调整它们的配置、工具和协作方式。

\paragraph{EvoAgentX}

\textbf{EvoAgentX}~\citep{evoagentx2024}提供了一个平台级的进化框架，支持多种进化策略的即插即用组合。用户可以选择不同的变异算子、选择机制和适应度函数，快速构建自定义的智能体进化流水线。

\subsubsection{混合方法的设计原则}

\begin{enumerate}
\item \textbf{最小侵入性}：新加入的进化机制不应破坏已有机制的功能
\item \textbf{信号隔离}：不同进化机制的奖励信号应独立，避免相互干扰
\item \textbf{优先级管理}：当多个机制产生冲突的改进建议时，应有明确的优先级规则
\item \textbf{可观测性}：每个机制的贡献应可独立度量，便于调试和优化
\end{enumerate}

\subsubsection{方法组合的理论基础}

不同类别的进化方法可以通过以下方式组合：

\textbf{串联组合}：方法 A 的输出作为方法 B 的输入。例如，Reflexion（提示词进化）生成反思文本，STaR（奖励进化）将这些反思作为训练数据。

\textbf{并联组合}：方法 A 和 B 同时运行，取更好的结果。例如，多个 Reflexion 并行运行，选择最优解。

\textbf{嵌套组合}：方法 A 的内部使用方法 B。例如，DGM（架构搜索）内部使用 Reflexion（提示词进化）来评估新架构。

\textbf{分层组合}：不同层级使用不同方法。例如，推理时使用 Self-Refine，训练时使用 STaR，架构层面使用 ADAS。

\subsection{开放问题}\label{sec:open-questions}
% =====================================================================

\subsubsection{Q1: 自我改进是否存在理论上限？}

是否存在一个固定的性能天花板，超过它之后任何自我改进方法都无法突破？从 Gödel 不完备定理的角度来看，一个系统的自我描述能力总是有限的。但 AlphaEvolve 在矩阵乘法上的突破（56 年来首次改进 Strassen 算法）暗示了：至少在某些特定领域，人类认知偏见可能比理论极限更早成为瓶颈。

\subsubsection{Q2: 如何评估自我改进的真实性？}

如何区分"真正的能力提升"和"对评估基准的过拟合"？RAGEN 的 Echo Trap 发现表明，即使是看似有效的训练过程也可能产生虚假的改进信号。我们需要：
\begin{itemize}
\item 更强的分布外评估基准
\item 改进信号的因果分析工具
\item 跨域迁移的标准测试协议
\end{itemize}

\subsubsection{Q3: 安全性与可控性的边界在哪里？}

自修改代码（Gödel Agent）和自生成训练数据（Absolute Zero）引入了根本性的安全挑战。如何确保：
\begin{itemize}
\item 自修改不会产生有害行为？
\item 自生成的训练数据不会引入偏见或后门？
\item 开放式进化（DGM）不会产生不可预测的系统行为？
\end{itemize}

\subsubsection{Q4: 最优的课程学习策略是什么？}

几乎所有方法都隐含了某种课程学习——从简单到困难的任务安排。Absolute Zero 将课程设计自动化，但其策略是否最优？理论上，最优课程应使学习进度最大化，但如何在实践中高效计算学习进度仍是一个开放问题。

\subsubsection{Q5: 不同方法的最优组合是什么？}

第六节的混合方法只是初步探索。给定一个具体任务，如何系统地选择和组合进化方法？这需要一个"元进化"框架——一个进化"如何进化"的系统。

\subsubsection{Q6: 记忆进化的规模化挑战如何解决？}

当 agent 运行数月甚至数年时，记忆库将达到数百万条目。如何在保持检索质量的同时控制存储和计算成本？现有的解决方案（AriadneMem 的图粗化、Memory-R1 的 RL 遗忘）在大规模设定下是否仍然有效？

\subsubsection{Q7: 架构搜索能否发现质变性的创新？}

ADAS 和 DGM 已经发现了超越人类设计的 agent 结构。但这些改进主要是"量变"——更高效的工具使用、更合理的提示词模板。架构搜索能否产生"质变"——发现全新的推理范式或认知架构？

\subsubsection{Q8: 自我进化与对齐目标如何协调？}

当 agent 同时追求自我改进和人类对齐目标时，两者可能产生冲突。例如，自我改进可能要求更大的自主性和更少的人类监督，而对齐可能要求相反的方向。如何在自我进化过程中保持对齐是一个根本性的挑战。

\subsection{本章小结}\label{sec:ch3-summary}
% =====================================================================

本章按六大类别系统梳理了 Agent Self-Evolution 的方法谱系：

\begin{enumerate}
\item \textbf{基于奖励的进化}（STaR, Self-Rewarding, Meta-Rewarding, RISE, RAGEN）：最成熟的方法类别，已有坚实的理论基础和丰富的实证验证。核心挑战是 Goodhart 风险和样本效率。

\item \textbf{自博弈进化}（Absolute Zero, SPIRAL, SPIN）：最具理论优雅性的方法类别——在零外部数据条件下实现自我改进。Absolute Zero 代表了这一方向的最新突破。核心挑战是模式坍塌和训练稳定性。

\item \textbf{提示词进化}（Reflexion, Self-Refine, ExPeL, ACE）：最易部署的方法类别——零训练成本，即插即用。核心洞察是"记忆替代梯度"。核心挑战是局部最优和上下文窗口限制。

\item \textbf{架构搜索}（ADAS, Gödel Agent, DGM, AlphaEvolve）：最具突破潜力的方法类别——在图灵完备的搜索空间中发现超越人类设计的 agent 结构。核心挑战是计算成本和安全性。

\item \textbf{记忆进化}（Voyager, Memory-R1, AriadneMem）：关注长期经验的积累与检索。核心挑战是记忆容量与检索效率的平衡。

\item \textbf{混合方法}（EvolveR, WebEvolver, HyperAgents, EvoAgentX）：组合多种机制实现端到端进化。核心挑战是设计原则的制定和贡献的独立度量。
\end{enumerate}

这些方法类别并非相互排斥，而是构成了一个连续的方法谱系。未来的研究方向包括：跨类别组合的理论基础、自我改进的真实性评估、安全性保障机制、以及从"量变"到"质变"的架构创新。

\subsection{方法谱系的历史演进}\label{sec:ch3-history}
% =====================================================================

Agent Self-Evolution 的发展可以划分为四个阶段，每个阶段对应着不同的核心范式和技术突破。

\subsubsection{第一阶段：推理时自我修正（2022-2023）}

以 Self-Refine 和 Reflexion 为代表。这一阶段的核心问题是：\textbf{在推理时不更新参数的情况下，模型能否通过自我反馈改善输出？}Self-Refine 给出了肯定的回答——同一模型通过 GENERATE-CRITIQUE-REFINE 循环，在七个任务上平均提升 20\%。Reflexion 进一步证明了"语义梯度"的有效性，在代码生成上超越了 GPT-4 零样本。

这一阶段的关键局限在于：改进受限于模型固有的评价能力。如果模型无法识别自己的错误，自我修正就无法进行。这直接催生了下一阶段的研究。

\subsubsection{第二阶段：训练时自我改进（2023-2024）}

以 STaR、Self-Rewarding、SPIN 为代表。核心问题是：\textbf{模型能否通过训练"学会"更好地自我评价和修正？}STaR 的合理化步骤将失败样本转化为可学习的正例，SPIN 将自博弈引入 SFT，Self-Rewarding 让模型同时提升生成和评判能力。

这一阶段的关键突破在于：自我改进不再是推理时的"免费附加"，而是成为可以通过训练优化的可学习行为。Meta-Rewarding 进一步解决了"谁来监督评判者"的问题。

关键局限在于：所有方法仍然依赖外部数据（标签或指令），无法完全自给自足。

\subsubsection{第三阶段：多轮强化学习与自博弈（2024-2025）}

以 RISE、RAGEN、Absolute Zero 为代表。核心问题是：\textbf{能否在完全零外部数据的条件下实现自我进化？}RISE 将自我修正建模为多轮 MDP并通过 RL 微调；RAGEN 发现了 Echo Trap 现象并提出了 StarPO 框架；Absolute Zero 实现了完全的零数据自博弈推理。

这一阶段的标志性成果是 Absolute Zero 获得 NeurIPS 2025 最佳论文奖，表明自博弈进化已成为主流研究方向。关键发现包括：代码自博弈可以迁移到数学推理，以及"更强的模型更善于让自己变得更强"。

关键局限在于：训练稳定性（模式坍塌风险）和评估真实性（如何区分真改进和过拟合）。

\subsubsection{第四阶段：架构搜索与开放进化（2024-2025）}

以 ADAS、DGM、Gödel Agent、AlphaEvolve 为代表。核心问题是：\textbf{能否自动化地发现超越人类设计的智能体架构？}ADAS 证明了跨模型迁移的可能性；DGM 通过开放式 archive 实现了持续进化；AlphaEvolve 在数学和工程上取得了突破性成果。

这一阶段的标志性事件是 AlphaEvolve 发现了 56 年来首个改进 Strassen 算法的矩阵乘法方案。这表明，至少在某些领域，机器发现的算法可以超越人类几十年的努力。

\subsection{方法组合的深度分析}\label{sec:ch3-combination}
% =====================================================================

\subsubsection{推理时 + 训练时的最优组合}

一个自然的组合策略是：推理时使用 Self-Refine / Reflexion 进行即时改进，训练时使用 STaR / RISE 进行权重更新。这种"双轨进化"的理论优势在于：
\begin{itemize}
\item 推理时的自我修正提供即时、细粒度的改进信号
\item 训练时的权重更新将高频的推理经验固化为低频的参数变化
\item 两者互补而非冗余——推理时改进处理"已知如何改进的情况"，训练时改进处理"需要学习如何改进的情况"
\end{itemize}

RISE 正是这种组合的典范——它通过 RL 训练使模型"学会"在推理时进行有效的自我修正。

\subsubsection{提示词进化 + 架构搜索的组合}

另一个有前景的方向是同时优化提示词和 agent 架构。ADAS 的搜索空间已经包含了提示词设计，但显式地将 Reflexion 式的反思机制嵌入搜索过程可能带来更高效的探索。

Agent Symbolic Learning 的"语言梯度"方法可以被视为这种组合的一种实现——它同时在自然语言空间中优化提示词、工具和流水线。

\subsubsection{记忆进化与其他类别的协同}

记忆进化是天然的"增广层"——它可以为任何其他方法提供经验积累和知识检索能力：
\begin{itemize}
\item \textbf{记忆 + 奖励进化}：将历史交互轨迹作为 RL 训练的 replay buffer
\item \textbf{记忆 + 提示词进化}：将过去成功的推理链作为 few-shot 示例
\item \textbf{记忆 + 架构搜索}：将过去的架构评估结果指导未来的搜索方向
\item \textbf{记忆 + 自博弈}：将自博弈中发现的有效策略存入技能库
\end{itemize}

\subsection{统一理论视角}\label{sec:ch3-unified}
% =====================================================================

\subsubsection{迭代放大框架}

所有六类方法可以统一在"迭代放大"（Iterated Amplification）框架下：

\begin{definition}[迭代放大]
设智能体的能力为 $C_t$，进化方法为 $M$，则：
\begin{equation}
C_{t+1} = M(C_t) + \epsilon_t
\label{eq:iterated-amplification}
\end{equation}
其中 $\epsilon_t$ 为噪声/回归项。如果 $M$ 是单调改进的（即 $C_{t+1} \geq C_t$ 几乎必然），则 $C_t$ 收敛到某个不动点 $C^*$。
\end{definition}

不同类别的方法对应不同的 $M$：
\begin{itemize}
\item \textbf{奖励进化}：$M$ 为 RL 优化步骤，$C$ 为策略空间
\item \textbf{自博弈}：$M$ 为自博弈训练，$C$ 为任务-策略联合空间
\item \textbf{提示词进化}：$M$ 为反馈-修订循环，$C$ 为上下文空间
\item \textbf{架构搜索}：$M$ 为 LLM 变异 + 选择，$C$ 为代码空间
\item \textbf{记忆进化}：$M$ 为经验积累与检索，$C$ 为知识空间
\item \textbf{混合方法}：$M$ 为上述方法的组合
\end{itemize}

\subsubsection{收敛性分析}

一个关键的理论问题是：迭代放大是否收敛？答案取决于三个条件：
\begin{enumerate}
\item \textbf{改进的单调性}：$M$ 是否总是产生改进？在实践中，由于评估噪声和 Goodhart 效应，这并不总是成立。
\item \textbf{改进的有界性}：每次改进的幅度是否递减？这决定了收敛速度。
\item \textbf{空间的有界性}：$C$ 的取值空间是否有上界？如果是（如模型参数空间），则理论上存在性能天花板；如果否（如代码空间），则改进可以无限持续。
\end{enumerate}

绝对零的实验结果暗示了令人兴奋的可能性：在代码和推理空间中，改进似乎尚未达到天花板。pass@1 和 pass@128 随训练持续提升，没有明确的收敛迹象。

\subsection{实践指南}\label{sec:ch3-practice}
% =====================================================================

\subsubsection{方法选择决策树}

基于任务特征选择合适的进化方法：

\begin{enumerate}
\item \textbf{是否有 GPU/训练资源？}
\begin{itemize}
\item 否 $\rightarrow$ 使用提示词进化（Reflexion, Self-Refine）
\item 是 $\rightarrow$ 继续
\end{itemize}

\item \textbf{是否有标注数据？}
\begin{itemize}
\item 有标签 $\rightarrow$ 使用 STaR
\item 有指令 $\rightarrow$ 使用 Self-Rewarding / Meta-Rewarding
\item 无数据 $\rightarrow$ 使用 Absolute Zero（需代码验证器）或 SPIRAL
\end{itemize}

\item \textbf{是否需要超越人类设计的架构？}
\begin{itemize}
\item 否 $\rightarrow$ 使用 RISE / RAGEN
\item 是 $\rightarrow$ 使用 ADAS / DGM（需大量 API 调用）
\end{itemize}

\item \textbf{任务是否需要长期经验积累？}
\begin{itemize}
\item 是 $\rightarrow$ 添加记忆进化组件（Voyager 式技能库）
\item 否 $\rightarrow$ 使用无记忆的方法
\end{itemize}
\end{enumerate}

\subsubsection{部署注意事项}

\textbf{成本控制}：架构搜索是最昂贵的方法类别。ADAS/DGM 在搜索过程中需要数千次 LLM API 调用。建议先用小规模搜索验证可行性，再扩展到完整搜索。

\textbf{评估设计}：所有方法的效果严重依赖于评估函数的质量。如果评估不可靠（如纯 LLM 评分），改进可能只是"迎合评分"而非真正提升。建议使用尽可能自动化的验证器（如代码执行、单元测试、形式化验证）。

\textbf{安全护栏}：对于自修改代码方法（Gödel Agent、DGM），建议：
\begin{itemize}
\item 在沙箱环境中运行
\item 设置明确的回滚机制
\item 限制代码修改的范围（如禁止文件系统操作、网络请求等）
\item 人工审核关键修改
\end{itemize}

\textbf{迭代监控}：在自我进化过程中持续监控以下指标：
\begin{itemize}
\item 目标任务性能（主指标）
\item 分布外任务性能（泛化指标）
\item 评估一致性（同一输入多次评估的方差）
\item 改进幅度趋势（是否接近收敛）
\end{itemize}

\subsection{与相关领域的关系}\label{sec:ch3-related}
% =====================================================================

\subsubsection{与神经架构搜索（NAS）的关系}

架构搜索方法（ADAS, DGM）可以被视为 NAS 在 agent 系统上的扩展。关键区别在于：
\begin{itemize}
\item NAS 的搜索空间是神经网络拓扑（连续或离散），而架构搜索的搜索空间是图灵完备的程序
\item NAS 使用梯度或进化算法搜索，而架构搜索使用 LLM 作为变异算子
\item NAS 评估单个网络在数据集上的性能，而架构搜索评估 agent 在任务集上的行为
\end{itemize}

AlphaEvolve 的 MAP-Elites 方法直接来源于 Quality-Diversity 进化计算文献。

\subsubsection{与持续学习（Continual Learning）的关系}

记忆进化方法（Voyager, Memory-R1）与持续学习共享核心挑战——如何在学到新知识的同时不遗忘旧知识（stability-plasticity dilemma）。但关键区别在于：
\begin{itemize}
\item 持续学习主要关注参数空间的灾难性遗忘
\item 记忆进化主要关注经验空间的知识管理和检索
\item 持续学习的目标是保持旧任务性能
\item 记忆进化的目标是利用旧经验提升新任务性能
\end{itemize}

\subsubsection{与元学习（Meta-Learning）的关系}

自我改进可以被视为一种特殊形式的元学习——"学会学习"。但关键区别在于：
\begin{itemize}
\item 传统元学习（如 MAML）在训练时学习好的初始化，测试时快速适应
\item 自我改进在部署后持续进化，没有明确的训练/测试划分
\item MAML 的元学习发生在参数空间，而许多自我改进方法（如架构搜索）发生在代码/结构空间
\end{itemize}

\subsubsection{与 AutoML 的关系}

AutoML 自动化机器学习流水线的设计（特征工程、模型选择、超参数优化）。Agent Self-Evolution 将自动化范围从"学习流水线"扩展到"整个智能体系统"：
\begin{itemize}
\item AutoML 优化固定结构的流水线参数
\item Agent Self-Evolution 优化智能体本身的结构、工具、记忆和策略
\item AutoML 在训练阶段完成后输出固定模型
\item Agent Self-Evolution 在部署后持续进化
\end{itemize}

ADAS 的作者明确将他们的工作定位为"Agent 版本的 NAS"，这一定位也暗示了 AutoML 的进化方向——从自动化学习到自动化智能。

\subsection{代码自我改进的深度分析}\label{sec:ch3-code-selfevolve}
% =====================================================================

代码自我改进是架构搜索的一个特殊但重要的子类——agent 通过修改自己的代码实现来提升能力。这一方向最近取得了显著进展，值得深入分析。

\subsubsection{SelfEvolve: 代码自我进化框架}

\textbf{SelfEvolve}~\citep{selfevolve2023}是一个两阶段流水线：

\textbf{阶段 1：自我生成知识}。与从外部文档检索不同，LLM 从其参数化知识中自我生成 API 文档或算法描述：
\begin{equation}
P(Y|K) = \prod_i p_\theta(Y_i | Y_{<i}, X, K)
\label{eq:selfevolve-knowledge}
\end{equation}
其中 $K$ 为自生成的知识。知识生成本身可以分解为：
\begin{equation}
p(K) = \prod_i p_\theta(K_i | c, K_{<i}) \times p_\theta(c | X)
\label{eq:selfevolve-decompose}
\end{equation}
其中 $c$ 为"试解"——模型先写一个简短的解决方案思路，再从中提取 API 使用知识。

\textbf{阶段 2：迭代自我精炼}。代码在 Python 沙箱中执行，如果出错，错误回溯被反馈给 LLM 进行迭代调试：
\begin{equation}
P(Y'|X,Y,K,e) = p_\theta(Y'|X,Y,e) \times p_\theta(Y|X,K)
\label{eq:selfevolve-refine}
\end{equation}
其中 $e$ 为错误消息。

\textbf{实验结果}：
\begin{itemize}
\item DS-1000（数据科学代码）：ChatGPT 49.4 $\rightarrow$ SelfEvolve \textbf{57.2}（+15.8\% 相对提升）
\item HumanEval（pass@1）：ChatGPT 74.39 $\rightarrow$ SelfEvolve \textbf{85.98}
\item TransCoder（C++ $\rightarrow$ Python）：ChatGPT 88.3\% $\rightarrow$ SelfEvolve \textbf{90.4\%}
\end{itemize}

SelfEvolve 的关键洞察是：LLM 可以同时作为知识提供者和自我反思的程序员。它不需要外部检索或特殊测试用例，完全依靠模型自身的知识和执行反馈。

\subsubsection{AI Scientist: 全自动化科学发现}

\textbf{AI Scientist}~\citep{aiscientist2024}（Sakana AI）将代码自我改进推向了极致——实现完全自动化的端到端研究流水线：

\begin{enumerate}
\item \textbf{想法生成}：LLM 生成新颖的研究想法，进行语义新颖性检查
\item \textbf{实验设计}：LLM 设计实验并生成 Python 代码
\item \textbf{代码执行}：自动化沙箱执行
\item \textbf{论文写作}：LLM 撰写完整的 LaTeX 论文
\item \textbf{自动化同行评审}：LLM 使用 ICLR 风格的评审标准评审论文
\end{enumerate}

评审分数计算为加权求和：
\begin{equation}
R = \sum_i w_i \cdot r_i
\label{eq:aiscientist-score}
\end{equation}
其中 $r_i$ 为 Soundness、Presentation、Contribution 等维度的分数。

\textbf{里程碑}：AI Scientist-v2 生成的论文获得了 workshop 级别的同行评审分数 \textbf{6.33}（top 45\%），成为第一篇通过同行评审的完全 AI 生成论文。

\textbf{局限性}：独立评估表明，AI Scientist 的自我评审过程拒绝了 9/10 篇论文（包括 4 篇人类接受的论文）；生成的论文缺乏理论深度和架构创新性；难以泛化到初始训练域之外（如 LSTM）。

\subsubsection{代码自我改进的层级}

代码自我改进方法可以按"改进深度"分层：

\begin{table}[htbp]
\centering
\caption{代码自我改进的层级分类。}
\label{tab:code-evolve-levels}
\begin{tabular}{llp{50mm}l}
\toprule
\textbf{层级} & \textbf{改进对象} & \textbf{描述} & \textbf{代表系统} \\
\midrule
L0: 错误修复 & 语法/运行时错误 & 基于执行反馈修复 bug & SelfEvolve \\
L1: 功能改进 & 算法/逻辑 & 改进算法效率或正确性 & FunSearch \\
L2: 架构修改 & 代码结构 & 修改 agent 的控制流、工具链 & ADAS, DGM \\
L3: 自我指涉 & 自身代码 & 修改用于修改代码的代码本身 & Gödel Agent \\
L4: 元进化 & 进化过程 & 优化"如何进化"的策略 & DGM (open-ended) \\
\bottomrule
\end{tabular}
\end{table}

层级越高，改进的潜在幅度越大，但同时风险和不确定性也越高。L0-L1 有明确的验证信号（代码是否通过测试）；L2-L4 的验证更加模糊（agent 是否"更好"取决于任务和评估标准）。

\subsubsection{代码验证的挑战}

代码自我改进面临一个核心的验证难题：如何确保修改后的代码确实更好？

\textbf{形式化验证}：使用形式化方法证明代码的正确性。这是最强但最昂贵的验证方式，仅适用于特定领域（如数学算法）。

\textbf{测试套件验证}：运行预定义的测试用例。这是最常见的验证方式，但存在测试覆盖率的局限——通过所有测试不代表代码在所有情况下都正确。

\textbf{性能基准验证}：在基准任务集上评估性能。这是 ADAS/DGM 采用的方式，但可能过拟合基准。

\textbf{人工审核}：人类专家审查代码修改。最可靠但最昂贵，无法规模化。

AlphaEvolve 在数学领域的成功部分归因于其拥有高质量的形式化验证器——可以确定性地区分改进和退化。对于大多数 agent 任务而言，这样的验证器并不存在，这是一个根本性的挑战。

\subsection{评估方法论}\label{sec:ch3-evaluation}
% =====================================================================

\subsubsection{评估维度}

Agent Self-Evolution 方法应在以下维度进行评估：

\begin{enumerate}
\item \textbf{目标性能}：在目标任务上的绝对性能（如 HumanEval pass@1）

\item \textbf{改进幅度}：相对于基线的改进（绝对值和相对值）
\begin{equation}
\Delta = \text{Perf}_{\mathrm{evolved}} - \text{Perf}_{\mathrm{baseline}}
\label{eq:improvement-delta}
\end{equation}

\item \textbf{改进效率}：每单位计算资源带来的改进
\begin{equation}
\eta = \frac{\Delta}{\text{Cost}_{\mathrm{total}}}
\label{eq:improvement-efficiency}
\end{equation}

\item \textbf{泛化能力}：改进是否迁移到分布外任务
\begin{equation}
G = \frac{\Delta_{\mathrm{OOD}}}{\Delta_{\mathrm{ID}}}
\label{eq:generalization-ratio}
\end{equation}
其中 ID 为训练域内任务，OOD 为域外任务。$G > 0$ 表示正迁移。

\item \textbf{稳定性}：多次运行的改进方差
\begin{equation}
S = 1 - \frac{\mathrm{Var}(\Delta)}{\max(\Delta)^2}
\label{eq:stability}
\end{equation}

\item \textbf{安全性}：进化过程中是否产生有害行为（需定性评估）
\end{enumerate}

\subsubsection{常见评估陷阱}

\textbf{基线选择偏差}：选择弱基线使改进看起来更大。例如，Reflexion 在 HumanEval 上的 91\% 是相对于 GPT-3.5 基线的 67\% 报告的。如果使用更强的基线（如 GPT-4 + few-shot），改进幅度会显著缩小。

\textbf{评估域偏移}：在训练域内评估可能高估泛化能力。Absolute Zero 在代码自博弈后测试数学推理是一个良好的实践——它显式地测试了跨域迁移。

\textbf{随机性忽视}：LLM 输出的随机性意味着单次运行的性能可能有较大波动。应报告多次运行的平均值和标准差。

\textbf{改进归因}：当使用多种技术组合时，难以将改进归因到具体技术。消融实验是必要的，但在计算成本较高的方法（如 DGM）中常常被省略。

\textbf{Echo Trap}：RAGEN 发现的"回声陷阱"表明，某些看似有效的训练过程实际上只是在教模型重复自己的输出。评估时需要检测推理过程中是否存在退化为复读的行为。

\subsubsection{推荐评估协议}

基于以上分析，我们推荐以下评估协议：

\begin{enumerate}
\item \textbf{多基准评估}：至少在两个不同类型的基准上评估（如代码+数学、推理+交互）
\item \textbf{多种子运行}：至少 3-5 次独立运行，报告均值和标准差
\item \textbf{跨域测试}：在训练域外测试泛化能力
\item \textbf{消融实验}：逐一移除组件以确定每个组件的贡献
\item \textbf{效率报告}：报告总计算成本（FLOPS、API 调用次数、GPU 小时）
\item \textbf{定性分析}：分析进化过程中发现的具体改进案例
\end{enumerate}
