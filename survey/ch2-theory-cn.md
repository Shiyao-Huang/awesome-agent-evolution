# 第2章：理论基础与五循环分类法

> 撰写时间戳：2026-05-26T20:00:00+08:00
> 英文真实源：`paper-drafts/ch2-taxonomy.tex`
> 素材来源：`raw-papers/`、`paper-reviews/`、`research/` 中截至 2026-05-26 已收集的 Agent Self-Evolution 论文。

## 2.0 本章概述

AI Self-Evolution 最好不被理解为单一算法、模型族或 benchmark，而是一族反馈循环——反复将系统从一个操作状态变换为另一个。共享模式很简单：系统提议变体，评估它们，保留一些关于发生之事的信息，并利用该信息改变未来行为。

本章提出围绕五个循环的分类法：**规格到执行循环**（Specification-to-Execution）、**搜索循环**（Search）、**评估器循环**（Evaluator）、**反思循环**（Reflection）和**种群循环**（Population）。这些循环不互斥，而是可组合的模块化机制。例如 AlphaEvolve 可解读为搜索+评估器+种群循环的组合；ADAS 可解读为规格到执行+搜索的组合；Reflexion 结合评估器信号与反思记忆。

## 2.1 统一形式化

令 $z_t$ 表示自进化 AI 系统在迭代 $t$ 的状态。状态可包括模型、提示词、记忆、agent 工作流、源代码仓库、benchmark 日志、候选 archive、数据缓冲区或这些产物的组合。

**紧凑进化方程：**

$$z_{t+1} = u(z_t, g(z_t), e(g(z_t)))$$

其中 $g$ 是候选生成算子，$e$ 是评估器，$u$ 是更新算子。

**展开形式：**

$$C_t = g(z_t), \quad F_t = e(C_t; z_t), \quad A_t = s(C_t, F_t, z_t), \quad z_{t+1} = u(z_t, A_t, F_t)$$

$C_t$=候选集，$F_t$=反馈对象，$A_t$=接受子集。

**状态因子分解：**

$$z_t = (m_t, p_t, a_t, c_t, d_t, h_t, \pi_t)$$

$m_t$=模型参数，$p_t$=提示词/指令，$a_t$=agent 架构，$c_t$=源代码，$d_t$=数据/示范，$h_t$=历史和记忆，$\pi_t$=评估/路由/选择策略。

不同方法操作不同坐标：反思循环主要修改 $h_t$ 和 $p_t$；提示词优化修改 $p_t$；ADAS 修改 $a_t$、$c_t$；代码进化修改 $c_t$；自博弈和 RL 修改 $m_t$ 和 $d_t$；种群方法修改状态集合 $\mathcal{Z}_t = \{z_t^{(1)}, \ldots, z_t^{(n)}\}$。

### 2.1.1 四个核心角色

形式化刻意分离四个角色：

- **生成（$g$）**——回答"接下来试什么？"
- **评估（$e$）**——回答"表现如何？"反馈对象可包含标量分数、通过/失败测试、语言批判、符号梯度、执行轨迹、反例、置信度估计、成本测量或安全违规
- **选择（$s$）**——回答"信任或保留什么？"
- **更新（$u$）**——回答"做什么持久变更？"

### 2.1.2 评估器强度谱系

| 强度 | 类型 | 代表 |
|------|------|------|
| 弱 | 语言自洽性、风格偏好 | Self-Refine 的自批判 |
| 中 | 外部反馈：答案正确性、奖励、人类偏好 | Reflexion 的环境信号 |
| 强 | 可执行、可重复、自动检查：单元测试、形式约束、编译器、证明检查器 | AlphaEvolve 的自动化评估器 |

**自进化的质量受限于评估器质量。** 评估器嘈杂→过拟合/奖励黑客；评估器昂贵→样本低效；评估器遗漏安全约束→任务指标提升但鲁棒性退化。

## 2.2 Loop 1：规格到执行循环（Specification-to-Execution）

将自然语言目标转换为可执行机器学习或智能体管线。

**核心步骤**：解析目标 → 推断缺失约束 → 设计可执行计划 → 实例化组件 → 运行计划 → 评估输出 → 修订。

### 2.2.1 代表系统

**AutoML-GPT**：使用 LLM 作为人类可读描述和 AutoML 组件之间的桥梁。自然语言作为 ML 实验的高层基因组——用户描述不直接执行，而是被编译为管线。

**AutoML-Agent**：将模式从单模型规划扩展到多智能体管线构建。数据获取、schema 检查、特征工程、模型选择、训练、评估、错误分析和部署被分配给专门智能体。智能体角色和管线阶段成为可变产物。

**ADAS** [Hu et al. 2024]：将循环从 ML 管线推广到智能体架构。搜索空间包括工具选择、推理模块、控制流、提示词、记忆布局和协作协议。生成的产物不只是模型，而是操作过程。

### 2.2.2 关键区分

**任务解释失败** vs **产物改进失败**。系统可能因为误解规格而失败（需要更好的需求获取），也可能因为正确理解任务但产出差解而失败（需要搜索、评估、反思机制）。许多 AutoML 和 agent 失败是混合的：指标正确但数据分割错误；agent 解决了可见任务但忽略延迟约束。

### 2.2.3 可执行表示的重要性

自然语言目标只有在被锚定为可运行和可检查的产物后才变得可进化。表示应足够结构化以支持评估和修订，又足够灵活以让 LLM 操作。这就是为什么许多系统使用中间卡片、计划、JSON-like schema 或代码模板。

## 2.3 Loop 2：搜索循环（Search）

探索可能产物的空间——提示词、指令、思维链模板、神经架构、ML 管线、agent 工作流、代码补丁、算法、超参数、工具选择、记忆策略或训练课程。

### 2.3.1 搜索方法谱系

**OPRO** [Yang et al. 2023]：最简单的 LLM 原生搜索模式。优化问题用自然语言描述，先前解和分数的历史放入提示词，LLM 被要求生成改进分数的新候选。LLM 充当优化器，上下文窗口包含压缩搜索历史。

**EvoPrompting** [Liu et al. 2023]：将思想应用于代码级神经架构搜索。LLM 提出架构代码，候选在任务上评估，进化操作引导未来提议。与传统随机变异相比，语义变异可以利用预训练知识；与梯度 NAS 相比，可以搜索难以松弛到连续空间的不规则程序结构。

**ADAS** [Hu et al. 2024]：搜索 agent 设计。搜索空间包括智能体数量、提示词、工具访问、规划策略、记忆使用和控制流。比提示词搜索更复杂因为候选评估需要运行完整智能体系统。改进可以是结构性的——候选 agent 可能因为不同的任务分解、更好的工具调用时机、自检或有用中间状态存储而胜出。

**AlphaEvolve** [Novikov et al. 2025]：大规模 LLM 引导的代码和算法进化搜索。基于 FunSearch 的洞见——LLM 生成的程序可由可执行评估器评分——同时扩展到更广泛的编码任务和种群管理。在五循环分类法中，AlphaEvolve 不仅是搜索方法，而是搜索+评估器+种群。

### 2.3.2 搜索空间选择

| 搜索空间 | 修改成本 | 评估鲁棒性 | 结构新颖性 |
|---------|---------|-----------|-----------|
| 提示词 | 低 | 难 | 低 |
| 超参数 | 低 | 易 | 有限 |
| 神经架构 | 高（需训练） | 易 | 中 |
| Agent 架构 | 中 | 难（需完整运行） | 高 |
| 代码 | 中 | 取决于测试质量 | 极高 |

### 2.3.3 局部 vs 全局搜索

**局部搜索**从现有方案出发提出小修改——"修复这个失败候选"。高效当现有方案已经强且评估器可靠时。

**全局搜索**广泛采样设计空间——"提出不同策略"。可以发现定性不同的解决方案。

种群和质量多样性方法结合两者：跨 niches 维护多个局部最优，允许探索而不丢弃专门化解。

### 2.3.4 反馈粒度

| 反馈类型 | 信息量 | 代表系统 |
|---------|-------|---------|
| 标量分数 | 低 | OPRO 分数排名 |
| 成对偏好 | 中 | 人类/AI 偏好 |
| 执行轨迹 | 高 | Self-Debug [Singh 2023] |
| 反例 | 高 | 失败测试用例 |
| 语言批判 | 中-高 | Reflexion [Shinn 2023] |
| 符号梯度 | 高 | Agent Symbolic Learning [Zhou 2024] |

更丰富的反馈通常提高样本效率，因为生成器可以定向变更。

## 2.4 Loop 3：评估器循环（Evaluator）

评估器是自进化系统合法性的核心来源。

### 2.4.1 评估器类型

1. **自评估**：同一模型批判自己的输出。灵活但不可靠。Self-Refine [Madaan 2023] 展示了可行性，也暴露了局限——产生错误的同一模型可能无法诊断它。

2. **环境/任务评估**：外部奖励信号、benchmark 分数、单元测试通过率。比自评估客观但可能不完整。Reflexion 使用环境成功信号 [Shinn 2023]。

3. **可执行验证**：代码执行器、编译器、证明检查器、形式约束。最强评估器。Absolute Zero 使用代码执行器验证自生成任务 [Zhao 2025]；AlphaEvolve 使用自动化评估器选择算法变体 [Novikov 2025]。

4. **人类偏好**：RLHF/RLAIF 标注。有价值但昂贵且多变。

5. **AI 评审**：LLM-as-a-judge。灵活但容易受长度偏好、位置偏差和奖励黑客影响。

### 2.4.2 Goodhart 定律

当指标成为目标，指标就会失真。因此自进化系统通常需要多目标优化：

$$\max_z \mathbb{E}[R(z)] - \lambda \text{Cost}(z) + \beta D(z) - \gamma \Omega(z) \quad \text{s.t. } C(z) = \text{true}$$

$R$=任务收益，Cost=成本，$D$=多样性，$\Omega$=复杂度，$C$=安全约束。

### 2.4.3 验证器审计原则

评估器是教师、法官和选择环境。验证器审计应包括：
- 对抗样本检查
- 校准检查
- 与人类一致性
- 对提示词变化的敏感度

## 2.5 Loop 4：反思循环（Reflection）

将失败转化为可复用知识。

### 2.5.1 机制

1. **轨迹存储**：记录完整执行轨迹
2. **失败归因**：确定失败原因
3. **经验压缩**：将轨迹压缩为可迁移洞察
4. **策略更新**：修改未来行为

### 2.5.2 代表系统

**Reflexion** [Shinn 2023]：actor 尝试任务 → evaluator 分配成功/失败 → reflection 模型写语言教训 → 记忆将教训带向未来。在 HumanEval 和交互式任务上产生大幅改进。但也暴露记忆管理问题：每次失败成为记忆→上下文增长；过度总结→丢失有用细节；反思过于泛化→增加 token 但不增加指导。

**ExPeL** [Zhong et al. 2023]：从多个任务经验中提取可迁移 insights。

**ACE** [ACERobot]：把上下文组织为可演化策略手册。

**ReasoningBank**：将成功和失败轨迹蒸馏为可检索推理策略。

**EvolveR**：把离线自蒸馏、在线交互和策略演化组织成生命周期。

### 2.5.3 记忆管理的核心张力

- 每次失败成为记忆 → 上下文膨胀
- 过度总结 → 有用细节丢失
- 反思过于泛化 → 增加 token 但不增加指导
- 后续系统在存储文本反馈时都继承这个权衡

## 2.6 Loop 5：种群循环（Population）

维护多个候选变体并随时间选择。

### 2.6.1 为什么需要种群？

单贪婪谱系可能丢弃不立即最优但包含有用构件的变体。Archive 保留多样性并支持累积创新。

**DGM** [Zhang et al. 2025]：将自改进从单谱系转化为种群过程。一个 agent 变体可能改进工具使用，另一个改进规划，第三个改进错误恢复。报告 SWE-bench 20.0%→50.0%，Polyglot 14.2%→30.7%。

**AlphaEvolve** [Novikov et al. 2025]：结合多个 Gemini 模型、自动化评估器和 MAP-Elites 风格保留。报告矩阵乘法、数据中心调度、芯片设计和注意力 kernel 的改进。

### 2.6.2 种群方法核心概念

- **Elite 保留**：保留每代最优个体
- **Niche/行为描述符**：按行为特征组织 archive
- **质量多样性**：同时优化性能和多样性
- **谱系追踪**：记录父-子关系
- **Stepping stones**：保留不立即最优但可能促进未来突破的变体

### 2.6.3 部署挑战

种群方法使部署更难：哪个变体应该用于哪个用户或任务？Archive 如果只保留高分候选可能过早收敛；如果保留所有候选成本和上下文压力迅速上升。

## 2.7 进化计算与 LLM 的结合

进化计算提供"生成—变异—选择—保留"的开放式搜索框架。LLM 改变了两个关键环节：

1. **LLM 是强语义变异器**：传统变异常常是随机扰动，LLM 可以根据失败原因生成有针对性修改。ADAS、DGM、SICA、AlphaEvolve 都把 LLM 作为高层 program mutation operator。

2. **LLM 可以参与评价与解释**：Self-Rewarding、Meta-Rewarding、IterAlign、ACE 和 EvolveR 都使用模型生成评价、原则、批评或策略总结。

### 2.7.1 五个设计维度

1. **表征**：候选个体是 prompt、policy、memory、tool plan、Python code、workflow graph 还是模型权重
2. **变异**：由随机扰动、LLM rewrite、反思文本、文本梯度、MCTS、RL update 还是程序 patch
3. **适应度**：由 benchmark、unit test、环境 reward、judge score、人类偏好、成本约束或安全规则定义
4. **选择**：保留最优/新颖/质量多样性/按领域分层/回滚门控
5. **继承**：通过权重/上下文/记忆库/代码库/技能库/原则库/archive 元数据

## 2.8 自我指涉与 Gödel 机器

Schmidhuber 的 Gödel 机器是形式化原型 [Schmidhuber 2003]。现代系统将形式证明放宽为经验验证。

**从证明到评估的转变**引入核心问题：当形式证明不可得时，什么样的经验验证足以支持自修改？经验型 Gödel agent 必须拆成受控层级：
- **可修改层**：prompt、工具、代码、策略
- **不可修改评估层**：必须隔离
- **沙箱执行层**：防止副作用
- **Archive 记录层**：保留谱系和回滚路径
- **人工审计层**：检查风险

### 能力反馈的递归结构

DGM 的关键洞见：更强的 coding agent 不仅能解决更多外部任务，也能更好地改进自己的代码。downstream task performance 与 self-modification capability 形成正反馈。ADAS 保留固定 meta agent（外源优化器模型），DGM 让被改进的 agent 继续承担自改进职责（内生优化器模型）。

## 2.9 元学习与自我改进的理论框架

LLM agent 的三层策略表示：

- **底层 θ**：基础模型参数（预训练+后训练）
- **中层 φ**：可编辑行为接口（系统提示、工具说明、planner、critic、代码模块、多智能体拓扑）
- **上层 m**：经验状态（记忆、技能库、原则库、失败反思、世界模型、archive）

广义策略：$\pi(a | s; \theta, \phi, m)$，自演化就是在反馈 $r$ 或评价 $e$ 的驱动下更新 $(\theta, \phi, m)$ 的一部分。

### 在线学习视角

每轮 $t$：agent 执行轨迹 $\tau_t$，评估器反馈 $f_t$，更新器 $U$ 产生 $z_{t+1} = U(z_t, \tau_t, f_t)$。

- θ 固定，m 更新 → 记忆型自演化（Reflexion）
- φ 更新 → 提示词/架构型自演化（ADAS、Agent Symbolic Learning）
- θ 更新 → 训练型自演化（RISE、RAGEN、Absolute Zero）
- E/任务生成器更新 → 自课程/自博弈（Absolute Zero）

## 2.10 自进化的数学形式化

智能体系统状态：$z = (\theta, c, g, m, A)$

- θ = 基础模型参数
- c = 上下文与提示词
- g = 工具、代码和控制流图
- m = 记忆、技能、原则与世界模型
- A = archive 或历史候选集合

更新过程：

$$z_{t+1}, A_{t+1} = S(A_t \cup \{U_k(z_t, x_t, y_t)\}_{k=1}^K; V, C, D)$$

$V$=评估器，$C$=约束检查，$D$=多样性度量，$S$=选择器。

### 改进的层次

| 层次 | 含义 | 验证难度 |
|------|------|---------|
| 局部改进 | 当前任务集得分上升 | 低 |
| 稳健改进 | 独立测试集上升 | 中 |
| 迁移改进 | 新任务分布或新模型上升 | 高 |
| 开放式改进 | Archive 持续产生新颖 stepping stones | 极高 |
| 安全改进 | 能力增长不伴随约束违背增加 | 极高 |

### 选择压力与 Goodhart 定律

评估器 $V$ 决定系统朝哪里演化：
- V=单元测试 → 优化通过测试
- V=LLM judge → 优化 judge 偏好
- V=环境 reward → 寻找 reward 漏洞
- V=人类偏好 → 过拟合标注分布

多目标优化：$\max_z \mathbb{E}[R(z)] - \lambda \text{Cost}(z) + \beta D(z) - \gamma \Omega(z)$ s.t. $C(z) = \text{true}$

## 2.11 理论边界

1. **无外部评估器时**，自我奖励可能陷入自洽幻觉
2. **任务分布过窄**，系统可能学习 benchmark-specific hacks
3. **可修改范围过大而约束不足**，系统可能破坏评估、日志或安全边界
4. **Archive 缺乏整理**，长期记忆带来噪声、冲突和上下文坍缩
5. **基础模型能力不足**，LLM 生成的变异可能无法跨越技术门槛

**Agent Evolution 不是魔法增长器**，而是把基础模型能力、外部反馈、搜索机制和工程约束耦合起来的优化过程。它能放大已有能力，也会放大评估器和环境设计中的缺陷。

## 2.12 小结

五循环分类法的核心洞见：
