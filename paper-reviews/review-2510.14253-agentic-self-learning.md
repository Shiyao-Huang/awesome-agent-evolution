## Summary

This paper investigates whether self-learning can scale LLM-based agents without relying on human-curated datasets or predefined rule-based rewards. Through controlled experiments in a search-agent setting, the authors identify two key determinants of scalable agent training: the source of reward signals and the scale of agent task data. Their key findings are: (1) rewards from a Generative Reward Model (GRM) outperform rigid rule-based signals for open-domain learning; (2) co-evolving the GRM with the policy further boosts performance; and (3) increasing the volume of agent task data -- even synthetically generated -- substantially enhances capabilities. Building on these insights, they propose Agentic Self-Learning (ASL), a fully closed-loop, multi-role reinforcement learning framework that unifies task generation, policy execution, and evaluation within a shared tool environment and LLM backbone. ASL coordinates three components -- a Prompt Generator, a Policy Model, and a Generative Reward Model -- to form a virtuous cycle of harder task setting, sharper verification, and stronger solving. Empirically, ASL delivers steady round-over-round gains, surpasses strong RLVR baselines (e.g., Search-R1) that plateau or degrade, and continues improving under zero-labeled-data conditions.

## Method Analysis

### Core Architecture

ASL is a three-role closed-loop RL system:

1. **Prompt Generator (Task Generator)**: This component generates task prompts that the Policy Model must solve. Crucially, the task generator co-evolves with the policy -- as the policy improves, the generator creates harder tasks to maintain the training challenge. This co-evolution prevents the common problem of agents overfitting to a fixed task distribution. The generator uses the LLM backbone to produce diverse, open-domain search tasks that probe different aspects of agentic capability.

2. **Policy Model (Agent)**: The agent that interacts with the search environment -- formulating queries, navigating results, extracting information, and producing answers. The policy is trained using reinforcement learning with reward signals from the GRM. As training progresses, the policy becomes more capable of handling the increasingly difficult tasks generated by the Prompt Generator.

3. **Generative Reward Model (GRM)**: Instead of rule-based reward signals (e.g., exact match, F1 score), ASL uses a generative LLM to evaluate the agent's outputs. The GRM can assess open-ended responses, provide nuanced scoring, and evaluate multi-step search trajectories. Critically, the GRM is also co-evolved with the policy -- it becomes a sharper judge as the policy becomes a stronger solver. This co-evolution ensures that the reward signal remains informative even as agent capabilities increase.

### Closed-Loop Training Cycle

The three components form a self-reinforcing cycle:
1. The Prompt Generator creates challenging tasks.
2. The Policy Model attempts to solve them, producing trajectories.
3. The GRM evaluates the trajectories, providing reward signals.
4. The Policy Model is updated using RL based on these rewards.
5. The Prompt Generator adapts to create harder tasks based on the policy's current capabilities.
6. The GRM adapts to provide more discriminating evaluations.
7. Repeat from step 1.

### Key Design Decisions

- **GRM over rule-based rewards**: The finding that generative rewards outperform rule-based signals is significant. Rule-based rewards (exact match, lexical overlap) are brittle and miss the nuance of open-domain search. GRM provides a more flexible evaluation that can assess answer quality even when the ground truth format differs from the agent's output.

- **Co-evolution of all three components**: Rather than fixing the task distribution and reward model (as in standard RL), ASL evolves all three components simultaneously. This co-evolution is essential for open-ended self-improvement: a static task distribution would be exhausted, and a static reward model would become uninformative as the policy improves.

- **Synthetic data at scale**: The finding that increasing synthetic task data improves performance challenges the assumption that data quality always trumps quantity. For agentic self-learning, volume -- even of synthetically generated tasks -- provides valuable training diversity.

- **Zero-labeled-data operation**: ASL's ability to continue improving without any labeled data is a critical capability for real-world deployment, where labeled data is expensive and may not exist for novel task domains.

### Controlled Experiments

Before proposing ASL, the authors conduct controlled experiments that isolate the contribution of each design choice:
- GRM vs. rule-based rewards: GRM wins for open-domain tasks.
- Co-evolving GRM vs. fixed GRM: Co-evolution provides additional gains.
- Scaling task data: More tasks (even synthetic) consistently improve performance.

These controlled experiments provide strong causal evidence for the design decisions in ASL.

## Contributions

### Novel Contributions

1. **Three-role co-evolution framework**: The Prompt Generator / Policy Model / GRM triad with mutual co-evolution is a clean architectural contribution. Each component pushes the others to improve, creating a self-reinforcing cycle that avoids the stagnation of fixed-task, fixed-reward training.

2. **GRM superiority over rule-based rewards**: The empirical demonstration that generative rewards outperform rule-based signals for open-domain agent training is an important practical finding. It suggests that the field should move toward learned evaluation for agent RL.

3. **Co-evolution of reward model with policy**: The finding that evolving the GRM alongside the policy provides additional gains over a fixed GRM is significant. It demonstrates that reward model staleness is a real problem in long-running agent training.

4. **Steady improvement under zero-labeled-data**: ASL's ability to continue improving round over round without any labeled data demonstrates genuine self-learning capability. This is the paper's strongest claim and most important result.

5. **Surpassing RLVR baselines**: Outperforming Search-R1 and other RLVR methods, which plateau or degrade, shows that ASL's closed-loop design avoids the convergence problems of standard approaches.

### Relationship to Prior Work

- **Search-R1 and RLVR methods**: ASL directly outperforms these approaches, which apply RL to verify search-augmented reasoning. ASL's advantage comes from the closed-loop co-evolution of tasks and rewards, which prevents the plateau that fixed-training approaches encounter.

- **Self-play methods**: ASL's co-evolution relates to self-play (the policy improving against itself), but uses a more structured three-role framework where separate components handle task generation, execution, and evaluation.

- **Absolute Zero and zero-data methods**: ASL shares the goal of training without labeled data, but applies it specifically to search agents with a more structured multi-role framework.

- **WebRL and web agent training**: ASL's search environment connects to the broader web agent training literature, but focuses on the search interaction specifically rather than full web navigation.

## Limitations

### Technical Limitations

1. **Search-specific evaluation**: The entire evaluation is conducted in a search-agent setting. Whether the three-role co-evolution framework transfers to other agent domains (embodied interaction, code generation, game playing) is untested. The search domain has specific properties (well-defined reward via answer correctness, discrete interaction steps) that may not generalize.

2. **GRM reliability**: Generative reward models can be inconsistent, biased, or gameable. The paper does not deeply analyze GRM failure modes -- cases where the GRM assigns high rewards to incorrect or low-quality responses. GRM reliability is a critical concern for any system that relies on it as the sole training signal.

3. **Round-over-round improvement may plateau**: While ASL shows steady gains in the reported experiments, the number of rounds is limited. Whether improvement continues indefinitely or eventually plateaus (as most training curves do) is unclear. The theoretical limits of co-evolution need investigation.

4. **Computational cost of three-component co-evolution**: Training three LLM-based components simultaneously is expensive. The paper does not provide cost analysis, making it difficult to assess whether ASL's gains justify its computational overhead compared to simpler approaches.

5. **No analysis of task diversity**: The Prompt Generator's task diversity is critical for avoiding overfitting. If the generator produces highly similar tasks, the policy may improve on a narrow subset of capabilities while neglecting others. The paper does not analyze task diversity metrics.

6. **Sensitivity to base LLM**: The three components all use the same LLM backbone. The system's performance is therefore bounded by the base model's capabilities. Weaker base models may not support the rich task generation, nuanced evaluation, and capable execution that ASL requires.

## Impact Assessment

### Novelty: 4/5
The three-role co-evolution framework (Prompt Generator / Policy Model / GRM) with mutual adaptation is a clean architectural contribution. The finding that GRM + co-evolution outperforms rule-based rewards is significant. The closed-loop self-learning paradigm is well-designed.

### Technical Quality: 4/5
Strong empirical methodology with controlled experiments isolating each design decision. The comparison against RLVR baselines that plateau while ASL continues improving is compelling. Main weaknesses are single-domain evaluation and lack of cost analysis.

### Clarity: 4/5
Well-organized with clear motivation, controlled experiments, and the final ASL framework. The three-role architecture is easy to understand. The writing effectively communicates the key findings and their implications.

### Significance: 4/5
ASL demonstrates that fully autonomous agent self-learning (zero labeled data, no rule-based rewards) is not just possible but can outperform supervised approaches. This has significant implications for the scalability of agent training.

### Overall: 4/5
A strong contribution to the agent self-learning literature. The three-role co-evolution framework provides a practical architecture for autonomous agent training. The key findings -- GRM superiority, co-evolution benefits, and zero-labeled-data improvement -- are well-supported by controlled experiments. The main limitation is the search-specific evaluation domain.

## Key Takeaways for awesome-agent-evolution

1. **Co-evolution of tasks, policy, and rewards is essential**: Fixed task distributions and fixed reward models lead to plateau. Co-evolving all three components creates a self-reinforcing cycle that sustains improvement over multiple rounds.

2. **Generative rewards outperform rules for open-domain learning**: Rule-based evaluation (exact match, F1) is too rigid for open-domain agent tasks. Generative reward models provide flexible, nuanced evaluation that better guides agent improvement.

3. **Synthetic data at scale is valuable**: Even synthetically generated tasks provide substantial training value when produced in sufficient volume. Self-generated data, when diverse enough, can replace curated datasets.

4. **Zero-labeled-data self-learning is achievable**: ASL demonstrates that agents can continue improving without any human-provided labels. This is the key capability for truly autonomous self-evolution.

5. **Three-role separation of concerns is a good design pattern**: Separating task generation, execution, and evaluation into distinct components with distinct evolution trajectories provides clean interfaces and enables independent optimization of each role.
