\subsection*{C.3 Benchmark disclosure template}

For arXiv-facing reproducibility, future revisions should attach this template to every benchmark claim:

\begin{enumerate}
\item \textbf{Evolving object}: output, prompt, memory, workflow, tool policy, code, weights, population, or data curriculum.
\item \textbf{Evaluator}: unit tests, hidden tests, reward model, human judge, formal verifier, execution trace, or production metric.
\item \textbf{Search budget}: turns, samples, candidates, tool calls, wall-clock time, tokens, dollars, and human review minutes.
\item \textbf{Split discipline}: train, validation, hidden test, time split, new task family, and contamination-control statement.
\item \textbf{Regression suite}: prior tasks, safety constraints, cost limits, permission boundaries, and negative-transfer cases.
\item \textbf{Audit and rollback}: versioned artifacts, accepted/rejected candidate logs, evaluator version, and rollback path.
\end{enumerate}

\section{Research Groups and Intellectual Lineage}
\label{app:researchers}

Self-evolution work connects several communities: evolutionary computation, AutoML/NAS, program synthesis, reinforcement learning, language-agent engineering, tool-use benchmarks, and AI safety. The lineage map is useful because it prevents the field from being read as only a 2024--2026 LLM trend.

\begin{itemize}
\item \textbf{Evolutionary computation lineage}: Schmidhuber's G\"{o}del machine, Clune's open-ended evolution and AI-GA framing, quality-diversity methods, MAP-Elites, and modern LLM-guided program evolution.
\item \textbf{Self-improvement and reasoning lineage}: STaR, Self-Refine, Reflexion, RISE, RAGEN, Absolute Zero, and related training-time or inference-time improvement loops.
\item \textbf{Agent architecture lineage}: ADAS, Agent Symbolic Learning, EvoMAC, G\"{o}del Agent, DGM, SICA, and workflow/agent-topology search.
\item \textbf{Code and algorithm discovery lineage}: FunSearch, AlphaEvolve, OpenEvolve, Science-CodeEvolve, and software-engineering agents evaluated on SWE-bench-like tasks.
\item \textbf{Memory and lifelong-agent lineage}: Voyager, ExpeL, ReasoningBank, Memory-R1, AriadneMem, Mem0, LangMem, Graphiti, and benchmark work on long-context or stateful agents.
\item \textbf{Safety and governance lineage}: evaluator tampering, reward hacking, memory poisoning, capability erosion, OEP, Misevolution, and production rollback/audit patterns.
\end{itemize}

\section{Release and Bilingual Versioning Notes}
\label{app:release-notes}

The English manuscript built from \texttt{paper-drafts/main.tex} is the arXiv-facing version. It should remain English-only in compiled output, avoid local system-font dependencies, and include all tables needed to support the survey claims. The Chinese companion material is maintained separately in the Chinese survey tree and in the Chinese appendix source so that bilingual readers can inspect the same evidence without mixing languages inside the arXiv PDF.

Before a public submission, the release bundle should pass the following gates:

\begin{enumerate}
\item Compile the English manuscript from a clean checkout with \texttt{xelatex}, \texttt{bibtex}, and two final \texttt{xelatex} passes.
\item Confirm that the English source set used by \texttt{main.tex} contains no Chinese characters.
\item Confirm that every benchmark number in Chapters 5 and Appendix~\ref{app:benchmarks} has a paper review, raw paper, or official report source.
\item Remove duplicate BibTeX aliases once citation keys are normalized.
\item Package only arXiv-needed sources: \texttt{main.tex}, English chapters, \texttt{appendix-en.tex}, bibliography files, and any figure assets actually referenced by the manuscript.
\item Keep Chinese companion outputs linked from the repository and website, but do not include them in the arXiv source tarball unless submitting a separate Chinese note.
\end{enumerate}
