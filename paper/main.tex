\begin{abstract}
AI self-evolution is not a single technique but a convergence of five fundamental loops: specification-to-execution, search, evaluator, reflection, and population. This survey systematically reviews the emerging landscape of self-improving AI systems, spanning 19+ open-source projects and 17+ foundational papers across five research communities---AutoML, Neural Architecture Search (NAS), LLM self-improvement, evolutionary computation, and autonomous agent frameworks. We propose a unified taxonomy that classifies existing work along the five evolution loops, revealing that progress in each community independently rediscovers mechanisms that others have formalized. We analyze self-improvement methods at both inference time (Self-Refine, Reflexion, Self-Debug) and training time (SPIN, STaR, Constitutional AI), trace the emergence of LLM-driven evolutionary optimization from OPRO to AlphaEvolve, and map the frontier of agent self-evolution from fixed architectures to open-ended self-modifying systems (Darwin G\"{o}del Machine, G\"{o}del Agent, Absolute Zero). We identify critical gaps in current agent frameworks and position Self-Evolve as the missing evolution layer above existing orchestration frameworks.
\end{abstract}

\section{Introduction}
\label{sec:introduction}
The history of artificial intelligence is characterized by alternating waves of static, hand-designed systems and adaptive, self-improving ones. Early expert systems required manual knowledge engineering; statistical machine learning introduced automated parameter fitting; deep learning automated feature engineering; and now, large language models (LLMs) are beginning to automate their own improvement. We stand at the threshold of a new paradigm: \textbf{self-evolving AI}---systems that can generate, evaluate, remember, and improve upon their own behavior without explicit human intervention at each step.

\subsection{From Static AI to Self-Evolving AI}
The trajectory from static to self-evolving AI can be understood through expanding automation scopes:
\begin{enumerate}
\item \textbf{Static systems} (pre-2012): Hand-crafted rules, features, and architectures.
\item \textbf{Learned representations} (2012--2017): Deep learning automated feature engineering.
\item \textbf{Architecture search} (2017--2020): NAS and AutoML automated model and pipeline design.
\item \textbf{Prompt-driven systems} (2020--2023): LLMs enabled natural language task specification.
\item \textbf{Self-evolving systems} (2023--present): Systems modify their own code, prompts, workflows, and architectures through iterative improvement cycles.
\end{enumerate}

\subsection{What is AI Self-Evolution?}
We define \textbf{AI self-evolution} as the capacity of an AI system to autonomously improve through iterative cycles involving:
\begin{itemize}
\item \textbf{Generation}: Producing candidate solutions, architectures, prompts, code, or behaviors.
\item \textbf{Evaluation}: Scoring candidates against objectives, benchmarks, or deployed metrics.
\item \textbf{Memory}: Storing successful and failed attempts for future reference.
\item \textbf{Improvement}: Using accumulated experience to produce better candidates.
\end{itemize}
This definition deliberately spans multiple communities. A prompt optimization system (OPRO) and an agent architecture search system (ADAS) both exhibit self-evolution, despite operating on different substrates and using different mechanisms.

\subsection{Relation to Existing Concepts}
AI self-evolution intersects with but is distinct from: \textbf{continual learning} (which updates on data streams, not system structure), \textbf{online learning} (parameter updates from streaming data), \textbf{self-supervised learning} (training signals from data itself), and \textbf{meta-learning} (learning how to learn, but typically within fixed architectures).

\subsection{Contributions}
\begin{enumerate}
\item A unified taxonomy of \textbf{five evolution loops} across five research communities (Section~\ref{sec:taxonomy}).
\item Systematic analysis of \textbf{19+ open-source projects} with detailed comparisons.
\item A \textbf{cross-domain perspective} unifying AutoML, NAS, LLM self-improvement, evolutionary computation, and agent frameworks.
\item Analysis of the \textbf{researcher ecosystem} and citation networks (Section~\ref{sec:landscape}).
\item Identification of \textbf{open problems} and a production roadmap (Section~\ref{sec:future}).
\end{enumerate}

\subsection{Specification-to-Execution Loop}
Translates natural language goals into runnable ML pipelines or agent workflows. \textbf{Representatives}: AutoML-GPT~\citep{automlgpt2023} uses GPT as a natural language bridge, converting task/model/data cards into complete ML pipelines. AutoML-Agent~\citep{automlagent2024} decomposes AutoML into specialized agents for data retrieval, preprocessing, modeling, evaluation, and deployment with retrieval-augmented planning and multi-stage validation.

\textbf{Loop dynamics}: User specifies task $\to$ system plans pipeline $\to$ executes $\to$ evaluates $\to$ refines specification understanding. The main gap is \textbf{persistent memory}---most systems start from scratch for each new task.

\subsection{Search Loop}
Explores the space of possible solutions using LLMs as intelligent search operators. \textbf{Representatives}: OPRO~\citep{yang2023opro} uses LLMs as general-purpose optimizers where solution-score history guides generation. EvoPrompting~\citep{chen2024evoprompting} treats LLMs as evolutionary operators for architecture code. ADAS~\citep{hu2024adas} automates search over agent design spaces. OpenEvolve~\citep{openevolve2024} provides open-source evolutionary code optimization.

LLM-driven search differs from traditional optimization through the model's ability to understand search space structure and propose semantically meaningful variations. Key mechanisms: temperature-controlled exploration, few-shot guidance from historical solutions, hash-based deduplication.

\subsection{Evaluator Loop}
Provides the fitness signal driving all other loops. Without reliable evaluation, generation is blind and search is random. \textbf{Representatives}: FunSearch~\citep{chen2024funsearch} achieves the first improvement over Strassen's algorithm in 56 years through LLM + automated evaluator. Self-Debug~\citep{chen2024selfdebug} uses execution feedback as self-repair signal.

\textbf{Evaluation modalities}: automated testing, benchmark suites (HumanEval, GSM8K, SWE-bench), execution traces, and deployment metrics. The evaluator loop is the \textbf{bottleneck} of self-evolution: as systems saturate benchmarks, marginal information gain decreases.

\subsection{Reflection Loop}
Converts failures into memory, feedback, and revised strategies. Unlike evaluators (scores), reflection produces \textit{explanations} and \textit{suggestions}. \textbf{Representatives}: Reflexion~\citep{shinn2023reflexion} introduces verbal reinforcement learning (91\% HumanEval pass@1 vs GPT-4's 80\%). Self-Refine~\citep{madaan2023selfrefine} demonstrates same-LLM generate-critique-rewrite. STaR~\citep{zelikman2022star} extends to training time with self-generated reasoning traces.

\subsection{Population Loop}
Maintains multiple candidates simultaneously, enabling selection, mutation, recombination, and specialization. \textbf{Representatives}: AlphaEvolve~\citep{novikov2025alphaevolve} uses MAP-Elites quality-diversity search with Gemini Flash + Pro, achieving 48 multiplications for $4\times4$ complex matrix multiplication (first Strassen improvement in 56 years), recovering 0.7\% worldwide Google compute. LLaMEA~\citep{lanzi2024llamea} evolves optimizers themselves. Darwin G\"{o}del Machine~\citep{zhang2025dgm} maintains open-ended archives (SWE-bench: 20\%$\to$50\%).

\section{Self-Improvement Methods}
\label{sec:self-improvement}

\subsection{Inference-Time Self-Improvement}

\subsubsection{Self-Refine}
Self-Refine~\citep{madaan2023selfrefine} demonstrates that a single LLM can generate, critique, and iteratively rewrite outputs at inference time. Applied to dialogue, code review, math reasoning, and sentiment reversal. The LLM's evaluation ability often exceeds its generation ability---separating these enables iterative gap-closing. 2--3 refinement iterations typically yield diminishing returns.

\subsubsection{Reflexion}
Reflexion~\citep{shinn2023reflexion} introduces persistent linguistic feedback. Three models: Actor $M_a$, Evaluator $M_e$, Self-Reflection $M_r$. Core loop: $a_e = M_a(\text{task}, M_{1:e-1})$, $r_e = M_e(a_e)$, $f_e = M_r(a_e, r_e)$, $M_e = M_{e-1} \cup \{f_e\}$. Achieves 91\% HumanEval pass@1 vs GPT-4's 80\%. The memory buffer acts as a ``verbal gradient'' replacing parameter updates.

\subsubsection{Self-Debug}
Self-Debug~\citep{chen2024selfdebug} uses execution feedback as self-repair signal. Unlike Self-Refine (internal critique) or Reflexion (linguistic feedback), Self-Debug grounds improvement in concrete runtime behavior---error messages, test outputs, and debugging information.

\subsection{Training-Time Self-Improvement}

\subsubsection{SPIN}
SPIN~\citep{spin2024} improves SFT models through self-play: the model generates responses, a previous-iteration critic distinguishes model from human outputs, and the model fine-tunes to become indistinguishable from human.

\subsubsection{STaR}
STaR~\citep{zelikman2022star} generates chain-of-thought rationales, filters correct ones, and fine-tunes on filtered sets. ``Reasoning generates reasoning''---successful traces become training data. Can leverage incorrect rationales by conditioning on correct answers for revision.

\subsubsection{Constitutional AI}
Constitutional AI~\citep{bai2022constitutional} introduces AI feedback self-alignment. Models generate, critique against constitutional principles, and revise. Demonstrates that LLMs can serve as their own reward signal.

\subsubsection{ReST}
ReST~\citep{gulrajani2023rest} combines self-generation with RL: generate multiple solutions, filter by correctness, fine-tune on filtered set using expectation-maximization.

\subsection{Inference vs.\ Training Trade-offs}
\begin{itemize}
\item \textbf{Cost}: Inference-time cheaper per use but repeated; training-time expensive upfront but amortized.
\item \textbf{Persistence}: Inference improvements ephemeral; training improvements persist in weights.
\item \textbf{Generality}: Inference methods task-specific; training improvements can generalize.
\item \textbf{Safety}: Inference processes visible in prompts; training modifications opaque.
\end{itemize}

\section{Evolutionary Code and Algorithm Discovery}
\label{sec:evolutionary-code}

\subsection{LLM as Optimizer: OPRO}
OPRO~\citep{yang2023opro} pioneered LLMs as general-purpose optimizers. The \textbf{two-layer prompt architecture}: outer meta-prompt (optimizer LLM, temp=1.0) contains sorted instruction-score pairs + few-shot examples; inner task prompt (scorer LLM, temp=0.0) applies generated instructions. Key details: 200 steps, 8 candidates/step, MD5 deduplication, 100-bin score bucketization, wrong-question tracking for dynamic few-shot selection. Cross-task generalization: GSM8K (+8\%), BBH, MMLU, linear regression, TSP.

\subsection{LLM as Evolutionary Operator}

\subsubsection{AlphaEvolve}
AlphaEvolve~\citep{novikov2025alphaevolve} combines: (1) Dual-model architecture: Gemini Flash (breadth) + Pro (depth). (2) MAP-Elites quality-diversity: $\text{Archive}[b(p)] = p$ if $f(p) > f(\text{Archive}[b(p)])$. (3) Automated evaluators. (4) Evolution context adaptation.

Results: 48 multiplications for $4\times4$ complex matrix mult (first Strassen improvement in 56 years); re-discovered SOTA for 75\% of 50+ math problems; recovered 0.7\% worldwide Google compute; 23\% FlashAttention speedup; 32\% attention speedup.

\subsubsection{LLaMEA}
LLaMEA~\citep{lanzi2024llamea} evolves meta-heuristic algorithms---``improving the improver.'' The LLM proposes optimization algorithms as code, evaluated on benchmarks. Best algorithms retained as parents.

\subsection{FunSearch}
FunSearch~\citep{chen2024funsearch} (Nature) combines LLMs with automated evaluators for mathematical program evolution. Key insight: \textbf{evaluator-constrained program evolution surpasses one-shot generation}. Results: new cap set records, bin packing improvements.

\subsection{Open-Source Implementations}
OpenEvolve~\citep{openevolve2024} (6,358 stars): community AlphaEvolve. SE-Agent: multi-trajectory revision/recombination. Science-CodeEvolve: scientific code evolution. SelfEvolve~\citep{jiang2023selfevolve}: self-generated knowledge + self-debugging (DS-1000: 49.4$\to$57.2, HumanEval: 74.39$\to$85.98).

\subsection{Challenges and Broader Impacts}
Challenges include evaluation cost scaling, search space design, reward hacking, reproducibility of LLM-generated results, and scalability to large software systems. FunSearch's mathematical discoveries and AlphaEvolve's infrastructure optimizations demonstrate significant broader impacts, but raise concerns about research displacement and capability concentration.

\section{Agent Self-Evolution Systems}
\label{sec:agent-evolution}

\subsection{Architecture Self-Evolution}

\subsubsection{ADAS}
ADAS~\citep{hu2024adas} automates search over agent architecture design spaces. The meta-agent proposes architectures, evaluates on tasks, and iteratively improves. Search space includes LLM call structure, prompt templates, tool integration, and control flow.

\subsubsection{G\"{o}del Agent}
G\"{o}del Agent~\citep{yin2024godel}: self-referential framework using LLM-driven monkey patching. Loop: (1) Read own code, (2) LLM proposes patches, (3) Apply at runtime, (4) Validate, (5) Rollback if degraded. Self-referential: $A' = \text{LLM}(A.\text{code}, \text{feedback}, \text{objective})$. Safety: rollback, validation, objective constraints.

\subsubsection{Darwin G\"{o}del Machine}
DGM~\citep{zhang2025dgm}: combines Darwinian evolution with G\"{o}del self-reference. Open-ended archive $A = \{a_1, \ldots, a_n\}$. Sampling: $P(a_i) \propto f(a_i) \times \text{diversity\_bonus}$. Modification: $a_{\text{child}} = \text{LLM}(a_{\text{parent}}.\text{code}, \text{edit})$. Selection: keep if improved. Results: SWE-bench 20\%$\to$50\%, Polyglot 14.2\%$\to$30.7\%. Open-endedness prevents convergence to single optimum.

\subsection{Workflow Self-Evolution}
AgentEvolver: evolutionary tool usage optimization. SE-Agent: multi-trajectory Revision/Recombination/Refinement.

\subsection{Memory and Learning}

\subsubsection{Agent Symbolic Learning}
Agent Symbolic Learning~\citep{wang2024agent_symbolic} (NeurIPS 2024): treats agents as symbolic networks. Algorithm: (1) Forward pass $\to$ trajectory $\tau$, (2) Language loss $\mathcal{L}_{\text{lang}} = \text{LLM}(\mathcal{P}_{\text{loss}}(\tau))$, (3) Language gradient backpropagation layer-by-layer, (4) Weight update via PromptOptimizer, ToolOptimizer, PipelineOptimizer. Results: HotPotQA F1 39.1, MATH 60.7\%, HumanEval 73.2\%.

\subsubsection{Absolute Zero}
Absolute Zero~\citep{zhao2025absolute_zero} (NeurIPS 2025 Award): model simultaneously proposes and solves tasks using only self-generated data. Dual-role: Task Proposer $\to$ Task Solver $\to$ Code Executor $\to$ RL update. Eliminates human-curated data dependency entirely.

\subsection{Multi-Agent Collaborative Evolution}
AutoML-Agent~\citep{automlagent2024}: multi-agent division of labor for full-pipeline AutoML. SelfEvolve~\citep{jiang2023selfevolve}: self-generated knowledge + self-debugging pipeline.

\subsection{Hierarchy of Self-Evolution}
(1) Output optimization (OPRO, Self-Refine), (2) Workflow optimization (AgentEvolver), (3) Architecture optimization (ADAS, G\"{o}del Agent), (4) Open-ended evolution (DGM, Absolute Zero). Each level subsumes the previous.

\section{AutoML and NAS Meets LLM}

\subsection{AutoML + LLM}
AutoML-GPT~\citep{automlgpt2023}: natural language bridge for complete ML pipelines. AutoML-Agent~\citep{automlagent2024}: multi-agent full-pipeline AutoML. Most production-ready self-evolution direction but lacks continuous evolution across runs.

\subsection{NAS + LLM}

\section{Open Problems and Future Directions}
\label{sec:future}

\subsection{Evaluation Bottleneck}
Benchmark saturation risks overfitting. As systems saturate HumanEval/GSM8K/SWE-bench, marginal information gain decreases. \textbf{Direction}: multi-dimensional evaluation, adversarial probing, meta-evaluation.

\subsection{Memory Stability and Drift}
Catastrophic forgetting, memory drift, unbounded growth. \textbf{Direction}: forgetting curves, experience replay, selective retention.

\subsection{Safety and Alignment}
Objective drift, reward hacking, unbounded modification, deceptive alignment. \textbf{Direction}: constitutional invariants, sandboxed execution, formal verification, interpretability tracking.

\subsection{Loop Composability}
Loop interactions poorly understood. \textbf{Direction}: formal composition frameworks, meta-evolution of loop configurations.

\subsection{Production Deployment}
Latency constraints, API costs, observability, version control, regulatory compliance. \textbf{Direction}: cost-aware infrastructure, regression gates, evolutionary version tracking.

\subsection{Self-Evolve Roadmap}
\begin{enumerate}
\item \textbf{Phase 1} (current): Instrumentation---evaluation layers, lineage tracking, cross-run memory.
\item \textbf{Phase 2}: Single-loop evolution with regression gates.
\item \textbf{Phase 3}: Multi-loop composition with resource allocation.
\item \textbf{Phase 4}: Open-ended evolution discovering new strategies.
\end{enumerate}

\section{Conclusion}
\label{sec:conclusion}
This survey presented a unified view of AI self-evolution through five fundamental loops. Our analysis of 19+ projects and 17+ papers across five communities reveals striking convergence: different communities independently rediscover the same self-improvement mechanisms. Self-evolving AI is an \textit{emergent capability} arising from the four primitives of generation, evaluation, memory, and improvement.

The frontier moves from fixed-architecture improvement toward open-ended self-modification (Darwin G\"{o}del Machine, G\"{o}del Agent, Absolute Zero). Significant challenges remain: evaluation bottleneck, memory stability, safety alignment, and loop composability. Self-Evolve is positioned as the missing evolution layer above existing frameworks, providing persistent evaluation, memory, lineage, and improvement. The convergence across communities suggests self-evolving AI is an active frontier with concrete results; the challenge is moving from isolated demonstrations to integrated, safe, reliable systems.
