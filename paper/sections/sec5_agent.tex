\section{Self-Evolving Agent Systems}
\label{sec:agent-evolution}

The evolutionary code systems of Section~\ref{sec:evolutionary-code} optimize programs---functions, heuristics, algorithms---within fixed architectural frameworks. A more radical form of self-evolution targets the \emph{agents} themselves: their architectures, workflows, tool configurations, and learning mechanisms. This section surveys the emerging landscape of self-evolving agent systems, from automated agent design to self-referential architectures, symbolic learning, and zero-data self-training.

\subsection{Automated Agent Architecture Search}
\label{sec:adas}

The design of agent architectures---prompting strategies, tool compositions, multi-step reasoning chains---has traditionally been a manual, intuition-driven process. ADAS~\citep{hu2024adas} (Automated Design of Agentic Systems) formalizes this as a search problem: given a space of possible agent architectures (expressed as Python programs) and an evaluation function, automatically discover high-performing designs.

\subsubsection{Meta Agent Search}

ADAS introduces the Meta Agent Search algorithm, in which a ``meta agent'' (an LLM, typically GPT-4o) iteratively proposes new agent architectures in code. The search space encompasses all valid Python programs that implement agents using a provided base class (\texttt{LLMAgentBase}), making it Turing-complete: any computable agent architecture can, in principle, be discovered.

The algorithm proceeds as follows:
\begin{enumerate}
\item \textbf{Initialization}: Seed the archive with known agent architectures (Chain-of-Thought, Self-Refine, LLM Debate, CoT with Self-Consistency, Quality-Diversity).
\item \textbf{Proposal}: The meta agent reviews the entire archive of previously discovered designs and their performance scores, then proposes a new agent architecture.
\item \textbf{Reflexion}: The proposal undergoes two rounds of self-reflection: first assessing novelty and identifying implementation errors, then correcting against a library of 10 common failure patterns.
\item \textbf{Evaluation}: The proposed architecture is dynamically loaded via \texttt{exec()} and evaluated on benchmark tasks with multi-threaded parallel execution.
\item \textbf{Archive update}: The new architecture and its score are added to the growing archive.
\end{enumerate}

The meta agent prompt includes the complete API specification of \texttt{LLMAgentBase}, the full history of discovered architectures, task examples, and explicit encouragement to ``think outside the box.'' The output format requires three fields: a structured \texttt{thought} section (insights + overall idea), a descriptive \texttt{name}, and the complete \texttt{code} implementation.

\subsubsection{Results and Cross-Domain Transfer}

On the ARC (Abstraction and Reasoning Corpus) benchmark, ADAS-discovered agents outperform all hand-designed baselines. The evolution trajectory shows clear architectural innovation: from initial seeds scoring 3--8\%, the system discovers a ``Memory-Augmented Agent'' at generation 4 that achieves 11\% by introducing a memory buffer---a design pattern not present in any seed architecture.

A striking finding is \textbf{cross-domain transfer}: architectures discovered on ARC transfer effectively to DROP, GPQA, MGSM, and MMLU, even without domain-specific adaptation. Moreover, architectures discovered using GPT-3.5 as the inner agent remain effective when GPT-4 serves as the backbone, demonstrating that the discovered designs encode general reasoning patterns rather than model-specific exploits.

ADAS was accepted at ICLR 2025 and received the NeurIPS 2024 Open-World Agent Workshop Outstanding Paper Award, with over 414 citations, establishing automated agent design as a recognized research direction.

\subsubsection{Limitations}

The computational cost of Meta Agent Search is substantial: each proposed architecture requires full benchmark evaluation, and the reflexion and debugging stages add multiple LLM calls per proposal. The archive grows indefinitely (no pruning), which can overwhelm the meta agent's context window at later generations. The approach is also limited to architectures expressible as Python programs using \texttt{LLMAgentBase}, excluding designs that require custom neural components, external memory systems, or non-textual modalities.

\subsection{Self-Referential Agent Architectures}
\label{sec:self-referential}

Beyond searching for agent architectures, a more radical approach allows agents to directly modify their own code at runtime. Two recent systems---the Darwin G\"odel Machine and G\"odel Agent---explore this direction, inspired by Schmidhuber's theoretical G\"odel Machine~\citep{schmidhuber2003godel}.

\subsubsection{Darwin G\"odel Machine (DGM)}

DGM~\citep{zhang2025dgm} combines Darwinian evolution with G\"odel machine self-reference. It maintains an open-ended archive of agent implementations, where each entry is a complete agent codebase paired with performance metrics. The evolution loop proceeds as follows:

\begin{enumerate}
\item \textbf{Sampling}: A parent agent is selected from the archive with probability proportional to fitness multiplied by a diversity bonus (favoring underexplored regions of the design space).
\item \textbf{Self-modification}: A foundation model (Claude or GPT) proposes code-level modifications to the parent agent, producing a child agent.
\item \textbf{Evaluation}: The child agent is evaluated on coding benchmarks.
\item \textbf{Selection}: If the child improves over the parent, it is added to the archive. Optionally, non-improving children may be retained for diversity.
\end{enumerate}

The ``open-ended'' nature of DGM distinguishes it from standard evolutionary algorithms that converge to a single optimum. By maintaining a diverse archive, DGM enables exploration of qualitatively different agent architectures and discovery of unexpected strategies.

\textbf{Key results}:
\begin{itemize}
\item \textbf{SWE-bench}: Improved verified resolution from \textbf{20.0\% to 50.0\%}---a 150\% relative improvement on the canonical software engineering benchmark.
\item \textbf{Polyglot}: Improved multi-language coding score from \textbf{14.2\% to 30.7\%}---a 116\% relative improvement.
\item Discovered novel agent structures not imagined by human designers.
\item Agents show cross-domain transfer: improvements learned on one benchmark benefit performance on others.
\end{itemize}

The same research group (UBC + Vector Institute, led by Jeff Clune) produced both ADAS and DGM, with DGM extending ADAS's search paradigm by adding open-ended archive evolution and removing the constraint of a fixed meta-agent architecture.

\subsubsection{G\"odel Agent}

G\"odel Agent~\citep{yin2025godelagent} (ACL 2025, Peking University + UCSB) takes a more direct approach to self-reference: it uses Python monkey patching to dynamically modify its own methods at runtime. Unlike DGM's archive-based evolution, G\"odel Agent modifies a single running instance.

The self-referential loop operates as:
\begin{enumerate}
\item \textbf{Runtime introspection}: The agent reads its own source code and current state.
\item \textbf{Modification proposal}: The LLM proposes specific code changes (monkey patches) guided by high-level objectives and recent performance feedback.
\item \textbf{Safe application}: Patches are applied at runtime via Python's \texttt{exec()} mechanism.
\item \textbf{Validation}: Modified code is tested on a validation set. If performance improves, the modification is accepted; otherwise, it is rolled back.
\end{enumerate}

\textbf{Key results}: On HotPotQA (multi-hop QA), G\"odel Agent achieves 8--15\% improvement over hand-designed agents. On ALFWorld (interactive text environments), improvement is significant. The agent demonstrates continuous improvement across task batches and discovers strategies that human designers did not anticipate.

\textbf{Safety mechanisms} include rollback capability for failed modifications, a validation step before committing changes, and high-level objective constraints that prevent drift. However, runtime self-modification introduces non-determinism, and the theoretical guarantees are weaker than formal G\"odel machine proofs. The approach is also Python-specific, limiting portability.

\subsubsection{Comparing DGM and G\"odel Agent}

While both systems draw inspiration from the G\"odel machine concept, they differ fundamentally in their approach:

\begin{itemize}
\item \textbf{Population vs.\ single agent}: DGM maintains an archive of agents (population-based search), while G\"odel Agent modifies a single running instance (individual self-modification).
\item \textbf{Offline vs.\ online}: DGM evaluates candidate modifications offline (run, evaluate, then decide), while G\"odel Agent applies changes online at runtime.
\item \textbf{Code mechanism}: DGM generates complete agent implementations, while G\"odel Agent applies targeted monkey patches.
\item \textbf{Open-endedness}: DGM's archive enables open-ended exploration; G\"odel Agent's single-instance modification is more focused but potentially faster.
\end{itemize}

Both approaches share the limitation that self-modification safety is addressed through engineering safeguards (rollback, validation) rather than formal verification. The question of how to provide rigorous guarantees for self-modifying systems remains open.

\subsection{Agent Symbolic Learning}
\label{sec:symbolic-learning}

Agent Symbolic Learning~\citep{zhou2024symbolic} (NeurIPS 2024, AIWaves + Zhejiang University) proposes an elegant unification: treating agents as symbolic networks where the ``weights''---prompts, tool definitions, and pipeline connections---can be optimized through a procedure analogous to backpropagation, but operating entirely in natural language space.

\subsubsection{Agent as Symbolic Network}

An agent is parameterized as a computational graph with three types of learnable nodes:
\begin{itemize}
\item \textbf{Prompt nodes} ($\mathcal{P}$): System prompts, persona descriptions, task instructions.
\item \textbf{Tool nodes} ($\mathcal{T}$): Function definitions and tool descriptions.
\item \textbf{Pipeline nodes} ($\mathcal{I}, \mathcal{O}$): Input/output connections between nodes that define the agent's computational flow.
\end{itemize}

The learning procedure mirrors neural network training:

\textbf{Forward pass}: The agent executes on a task, producing a trajectory $\tau$ of actions and observations.

\textbf{Language loss}: An LLM evaluates the trajectory and produces a natural language description of what went wrong:
\begin{equation}
\mathcal{L}_{\text{lang}} = \text{LLM}(\mathcal{P}_{\text{loss}}(\tau))
\end{equation}

\textbf{Language gradient backpropagation}: Working backward from the output layer to the input, the system computes a ``language gradient'' for each layer---a natural language description of how to improve that component:
\begin{equation}
\nabla_{\text{lang}}^n = \text{LLM}(\mathcal{P}_{\text{gradient}}(\nabla_{\text{lang}}^{n+1}, \mathcal{I}_n, \mathcal{O}_n, \mathcal{P}_n, \mathcal{T}_n, \mathcal{L}_{\text{lang}}))
\end{equation}

\textbf{Weight update}: Three specialized optimizers update different components:
\begin{itemize}
\item \textbf{PromptOptimizer}: $\Delta\mathcal{P} = \text{LLM}(\mathcal{P}_{\text{update}}(\mathcal{P}, \nabla_{\text{lang}}))$
\item \textbf{ToolOptimizer}: $\Delta\mathcal{T} = \text{LLM}(\mathcal{P}_{\text{update}}(\mathcal{T}, \nabla_{\text{lang}}))$
\item \textbf{PipelineOptimizer}: $\Delta\mathcal{I}, \Delta\mathcal{O} = \text{LLM}(\mathcal{P}_{\text{update}}(\mathcal{I}, \mathcal{O}, \nabla_{\text{lang}}))$
\end{itemize}

The ``language gradient'' $\nabla_{\text{lang}}$ is a textual description propagated through the agent's computational graph, analogous to gradients in neural networks but operating in the space of natural language.

\subsubsection{Results}

Agent Symbolic Learning demonstrates broad effectiveness across diverse benchmarks:

\begin{itemize}
\item \textbf{HotPotQA}: F1 of 39.1 (vs.\ 37.4 for DSPy, 36.2 for baseline agents)
\item \textbf{MATH}: 60.7\% accuracy (vs.\ 56.0\% for baseline, 48.4\% for DSPy), using GPT-4 backbone
\item \textbf{HumanEval}: 73.2\% pass@1 (vs.\ 68.3\% baseline)
\item \textbf{Software Development}: Average score 3.8 on 1--4 executability scale (vs.\ 2.4 for agents, 1.6 for GPTs)
\item \textbf{Creative Writing}: 7.4 on 1--10 scale (vs.\ 6.8 for Tree of Thought)
\end{itemize}

These improvements are achieved without any weight updates to the underlying LLM---all optimization occurs in the space of prompts, tools, and pipeline connections.

\subsubsection{Relationship to Other Paradigms}

Agent Symbolic Learning extends DSPy's prompt optimization concept to the full agent architecture, including tools and pipeline structure. It is related to Reflexion's verbal reinforcement learning but uses structured backpropagation through a computational graph rather than episode-level reflection. The approach precedes and informs code-level self-modification methods (DGM, G\"odel Agent) by demonstrating that agents can be meaningfully optimized through natural language ``gradients.''

\subsubsection{Limitations}

The method requires a strong LLM backbone (GPT-4 level) for gradient computation---weaker models produce less informative language gradients. The quality of optimization depends on the design of loss, gradient, and update prompt templates, introducing a manual engineering component. There are no theoretical convergence guarantees for optimization in language space. Finally, each training step requires multiple LLM calls (forward + loss + backpropagation through all layers + weight update), making it computationally expensive.

\subsection{Self-Evolving Code Generation Pipelines}
\label{sec:selfevolve}

SelfEvolve~\citep{jiang2023selfevolve} (Shanghai Jiao Tong University + Shanghai AI Lab) demonstrates a simpler but effective form of self-evolution for code generation: a two-stage pipeline where the LLM first generates its own API documentation, then iteratively debugs its generated code using execution feedback.

\subsubsection{Self-Generated Knowledge}

Stage 1 addresses a common failure mode in LLM code generation: hallucinated API usage. Rather than relying on external documentation (which may be incomplete, outdated, or poorly matched to the task), SelfEvolve prompts the LLM to generate its own API documentation from its parametric knowledge. This self-generated knowledge $K$ conditions the subsequent code generation:
\begin{equation}
P(Y|K) = \prod p_\theta(Y_i | Y_{<i}, X, K)
\end{equation}
where $X$ is the task description and $K$ is the self-generated documentation.

\subsubsection{Iterative Self-Refinement}

Stage 2 implements a sandbox-based feedback loop:
\begin{enumerate}
\item Generated code is executed in a Python interpreter sandbox with test cases derived from the problem description.
\item If execution fails, the full error traceback is fed back to the LLM.
\item The LLM revises the code based on the error message.
\item Steps 1--3 repeat until the code passes or a maximum iteration count is reached.
\end{enumerate}

The revision probability is:
\begin{equation}
P(Y'|X,Y,K,e) = p_\theta(Y'|X,Y,e) \times p_\theta(Y|X,K)
\end{equation}
where $e$ is the error message from the previous execution attempt.

\subsubsection{Results}

On DS-1000 (data science code), SelfEvolve achieves 57.2 pass@1, a 15.8\% relative improvement over the ChatGPT baseline (49.4). On HumanEval, it reaches 85.98 pass@1 (vs.\ 74.39 for ChatGPT), approaching GPT-4's 89.95. On TransCoder (C++ to Python), it achieves 90.4\% accuracy (vs.\ 88.3\% for ChatGPT).

SelfEvolve represents an early but important form of self-evolution: the system improves its own output through feedback from its own execution environment, without external evaluation or human intervention. It is a direct precursor to later, more sophisticated self-evolution frameworks.

\subsection{Zero-Data Self-Training: Absolute Zero}
\label{sec:absolute-zero}

The most extreme form of self-evolution eliminates all external dependencies: no human-curated training data, no external evaluation functions, no hand-designed curricula. Absolute Zero~\citep{zhao2025absolutezero} (NeurIPS 2025 award-winning, Tsinghua University / LeapLabTHU) achieves this through self-play reinforcement learning.

\subsubsection{Self-Play RLVR}

Absolute Zero introduces the Self-Play Reinforced Learning with Verifiable Rewards (Self-Play RLVR) paradigm. A single model simultaneously serves two roles:

\textbf{Task Proposer}: Generates new reasoning tasks (code, math, logic puzzles) based on the current curriculum state. The proposer is rewarded for generating tasks that are solvable but challenging:
\begin{equation}
R_{\text{proposer}} \propto \text{difficulty}(t) \times \text{solvability}(t)
\end{equation}

\textbf{Task Solver}: Attempts to solve the proposed tasks. Solutions are verified by a code executor, providing a binary reward signal.

Both roles are updated via reinforcement learning (PPO/GRPO), creating a self-improving loop: better tasks $\rightarrow$ better training signal $\rightarrow$ better solver $\rightarrow$ better proposer (via reward for proposing solvable-but-hard tasks).

The dual-role architecture ensures that the system does not degenerate into trivial self-agreement. The proposer must generate tasks that the solver can verify (not trivially impossible) but finds challenging (not trivially easy), while the solver must develop genuine reasoning ability to handle tasks of increasing difficulty.

\subsubsection{Results}

AZR-Coder-7B, trained with zero external data, achieves state-of-the-art results among 7B-parameter models on:
\begin{itemize}
\item \textbf{HumanEval+}: SOTA at 7B scale
\item \textbf{MBPP+}: SOTA at 7B scale
\item \textbf{Overall average}: SOTA at 7B scale across coding and math benchmarks
\end{itemize}

A striking finding is \textbf{cross-domain transfer}: training only on self-generated code tasks produces competitive mathematical reasoning on GSM8K and MATH, despite zero mathematical training data. This suggests that the self-play process develops general reasoning capabilities, not domain-specific tricks.

The scaling behavior follows a clear pattern: ``stronger models are better at making themselves stronger''---larger or more capable base models produce better self-play dynamics and achieve higher final performance.

\subsubsection{Limitations and Risks}

Task quality depends on the proposer's current capability, creating a bootstrapping challenge (early training may produce trivial or unsolvable tasks). The code executor limits task types to verifiable programming problems, excluding domains without automated verification. Mode collapse---where the proposer and solver converge to trivial agreements---is a risk, though the dual-role reward structure mitigates it. The computational cost of dual-role RL training is significant.

\subsection{Reflective and Iterative Self-Improvement}
\label{sec:reflection-agents}

Before the systems described above, the foundational work on agent self-improvement established the paradigm of iterative refinement through self-feedback. Two papers are particularly important for understanding the intellectual lineage of self-evolving agents.

\subsubsection{Reflexion: Verbal Reinforcement Learning}

Reflexion~\citep{shinn2023reflexion} (NeurIPS 2023, Northeastern University + MIT/Princeton) introduces verbal reinforcement learning: agents learn from linguistic feedback stored in a growing memory buffer, without any weight updates.

The architecture comprises three specialized models:
\begin{itemize}
\item \textbf{Actor} ($M_a$): Generates actions given the task and accumulated memory.
\item \textbf{Evaluator} ($M_e$): Scores the actor's output (binary or scalar reward).
\item \textbf{Self-Reflection} ($M_r$): Generates verbal feedback explaining what went wrong and what to do differently.
\end{itemize}

The reflexion loop stores failure analyses in a memory buffer $M$ that grows across episodes:
\begin{equation}
M_e = M_{e-1} \cup \{f_e\}, \quad f_e = M_r(a_e, r_e, \text{task})
\end{equation}

This memory acts as a ``verbal gradient''---natural language guidance for future attempts, analogous to parameter gradients in neural network training but operating in text space.

On HumanEval, Reflexion achieves \textbf{91\% pass@1} using GPT-3.5, surpassing GPT-4's 80\%---a striking demonstration that iterative self-reflection with a weaker model can outperform single-pass generation with a stronger model. On AlfWorld, Reflexion reaches 97\% success (vs.\ 75\% baseline).

Reflexion's key insight---that episodic memory of failures can serve as a training signal for language agents---directly influenced all subsequent work on self-evolving agents, from Agent Symbolic Learning's structured backpropagation to DGM's archive-based evolution.

\subsubsection{Self-Refine: Iterative Refinement with Self-Feedback}

Self-Refine~\citep{madaan2023selfrefine} (NeurIPS 2023, AI2 + Google + CMU) demonstrates that a single LLM can iteratively generate, critique, and refine its own output across seven diverse tasks, achieving approximately 20\% average improvement with no external feedback, no training, and no reinforcement learning.

The three-step loop (GENERATE $\rightarrow$ CRITIQUE $\rightarrow$ REFINE) repeats until the critique identifies no further improvements or a maximum iteration count is reached. The same model serves all three roles. On sentiment reversal (74\% $\rightarrow$ 86\%), dialogue response (52\% $\rightarrow$ 68\% win rate), and constrained generation (65\% $\rightarrow$ 78\% compliance), Self-Refine produces consistent improvements.

Self-Refine establishes the principle that self-feedback is a viable alternative to external feedback, a foundational assumption underlying all subsequent self-evolution systems.

\subsubsection{Evolution Targets}

\textbf{Architecture evolution} (ADAS, DGM, G\"odel Agent) modifies the structural design of the agent itself---its reasoning flow, tool usage patterns, and control logic. This is the most ambitious target, as it can discover entirely novel agent designs that human engineers did not conceive.

\textbf{Workflow evolution} optimizes the sequence of operations an agent performs---which tools to use, in what order, with what parameters. This is less ambitious than architecture evolution but more tractable and directly applicable to production systems.

\textbf{Knowledge evolution} (Agent Symbolic Learning, SelfEvolve) modifies the agent's prompts, tool descriptions, and internal knowledge representations. This is the most fine-grained target and can be applied within fixed architectures.

\textbf{Memory evolution} (Reflexion) accumulates experiential knowledge in a growing memory buffer. Rather than modifying the agent's structure or parameters, it enriches the agent's context with lessons from past failures.

\textbf{Weight evolution} (Absolute Zero) modifies the underlying model parameters through self-play reinforcement learning. This is the only target that changes the model's internal representations, as opposed to its external behavior.

\subsubsection{Evolution Mechanisms}

\textbf{Search-based} (ADAS, DGM): A meta-agent or evolutionary algorithm proposes candidate designs, which are evaluated and selected. This approach explores a broad space but is computationally expensive.

\textbf{Gradient-based} (Agent Symbolic Learning): Language-space gradients guide optimization through the agent's computational graph. This is more targeted than search but depends on the quality of language gradient computation.

\textbf{Self-play} (Absolute Zero): The agent generates its own training data and evaluation signal through a dual-role setup. This eliminates external dependencies but is limited to verifiable domains.

\textbf{Reflexive} (Reflexion, Self-Refine): The agent reflects on its own failures and generates improvement guidance. This is the simplest mechanism but may not discover fundamentally novel strategies.

\subsection{Limitations and Open Challenges for Agent Self-Evolution}
\label{sec:agent-limitations}

Despite rapid progress, self-evolving agent systems face significant challenges that the current literature has not fully addressed:

\textbf{Evaluation reliability.} All systems rely on benchmark-based evaluation to guide evolution. However, benchmark improvement does not necessarily correlate with genuine capability gain. Agents may evolve to exploit benchmark-specific patterns (e.g., answer distribution biases, prompt format regularities) rather than developing general reasoning ability. DGM's SWE-bench improvement from 20\% to 50\% is impressive, but the generalizability of the evolved strategies to real-world software engineering tasks remains an open question.

\textbf{Stability of self-modification.} Self-modifying systems risk destabilization: a sequence of individually beneficial modifications may collectively degrade performance. G\"odel Agent's rollback mechanism addresses this locally, but there is no guarantee against gradual drift. DGM's archive-based approach is more robust (each modification is evaluated against the parent), but the computational cost grows with archive size.

\textbf{Scalability.} Current evaluations are limited to relatively narrow benchmarks. ADAS uses ARC, DROP, GPQA, MGSM, and MMLU; DGM uses SWE-bench and Polyglot. Whether these approaches scale to the complexity of real-world agent applications---multi-day workflows, large codebases, ambiguous objectives---is unclear.

\textbf{Safety and alignment.} Self-evolving agents that modify their own code raise fundamental safety questions. A system that can rewrite its own behavior is, by definition, harder to constrain. Current safety mechanisms (rollbacks, validation sets, objective constraints) are engineering-level mitigations, not formal guarantees. As agent self-evolution moves toward practical deployment, alignment between evolved behavior and human intent becomes increasingly critical.

\textbf{Theoretical foundations.} The field lacks formal frameworks for reasoning about self-evolving systems. Under what conditions does agent self-modification converge to improved behavior? What are the theoretical limits of open-ended agent evolution? These questions remain largely unaddressed.

\textbf{Resource requirements.} All systems surveyed require significant compute: ADAS and DGM use GPT-4 class models for the meta agent; Absolute Zero requires dual-role RL training; Agent Symbolic Learning needs multiple LLM calls per training step. Democratizing agent self-evolution requires more efficient methods.

These limitations connect to the broader open problems discussed in Section~\ref{sec:open-problems}, particularly the evaluation bottleneck (Section~\ref{sec:evo-limitations}), the safety challenge, and the gap between benchmark performance and real-world utility. The transition from evolutionary code discovery (Section~\ref{sec:evolutionary-code}) to agent self-evolution represents a shift from optimizing the \emph{tools} that AI uses to optimizing the \emph{agents} that use them---a shift that amplifies both the potential and the risks of self-evolving AI.
